# JA-1 S3 C11

C11 lets the Studio play the Current edit while a host holds the project. Before C11, a saved project with its host attached could not show the Current edit at all; see c10.md, "When Current-edit playback is unavailable".

## Design

C11 extends C9's snapshot lease. It adds no new contract: the host already has the owner epoch, the current input manifest and durable manifest objects.

- **Scope.** `HostStatus.playback_scope` is `(owner epoch, current inputs ref)`. Every reply and the status heartbeat (about 1 s) carry it. `studio_playback_scope()` reads it while host-attached.
- **Lease.** `HostCommand::LeaseCurrentEdit { inputs }` leases only the host's current inputs. It uses C9's access check and its cap of 64 leases. Viewers and Editors may lease; Producers are refused. The lease (`CurrentEditLease`) pins the closure of the input manifest and carries a digest-bound graph manifest. Nothing else becomes readable.
- **Ending.** The lease status check refuses (`lease_revoked`) once the owner epoch or the current inputs move. Every lease command first drops stale current leases and their pins. Release, Save As, rescue, host death and Close also end the lease. The host ends it at once, but the App's reads stop within a bound, not at once: see "Revocation bound" under Limits.
- **Reader.** The App opens a `CurrentEditReader`: a read-only, hash-checked store at the project path, with lease-bound read authority. It admits `PlaybackInputs` for the App's accepted document. The leased authority is bound to those inputs (`manual_playback_inputs`, `studio_store.rs`), so every later read and retarget checks the lease.
- **Why not lease the head.** Checkpoints are written only at Save, so an unsaved manual edit has no checkpoint object to lease. The current edit's immutable part is its input graph; the document comes from the App's accepted history.

### Smoothness

- **Ordinary edits.** An edit by the person or the agent keeps the scope, so the Studio keeps its lease and retargets with `PlaybackInputs::with_document`. Nothing reopens and nothing flashes.
- **Scope changes.** Save As, rescue and media import change the scope, and the Studio renews the lease. While it renews, the presenter keeps the last frame, marked stale, until the new frame binds.
- **Previous inputs.** The brief says "keep the previous inputs until the new ones are ready". C11 keeps the previous picture, not readable previous inputs. The host ends the old lease when the inputs move, so the App can never keep reading the old head; that is the mutation guard below.

## Limits

- **Agent-side scope moves.** An agent import moves the host's inputs and ends the old lease at once. The App learns the new scope from the next status heartbeat, about 1 s later. Until then, reads of the old inputs fail, and the Studio shows its last frame until it renews. The person's own Save As, import and rescue carry the new status in their reply, so they renew at once.
- **Revocation bound.** When the inputs or the epoch move, or the host dies, the App can still read for up to 250 ms after its last good probe, because C9's lease check caches a positive answer for that long. A read that passed its check before the revocation also finishes. After that, reads stop. The heartbeat does not set this bound; it only sets when the App learns the new scope.
- **Unsaved imports.** Media imported while unsaved is playable only if its manifest object is on disk. If it is not, opening the lease fails, and the Studio reports it once.
- **Not covered.** Native Windows, hosted CI, review rounds and push.

## Follow-up 1

Both reviews of C10+C11 approved with Minors. Both found the same playback latch (Astra M1, Muse M1). Follow-up 1 fixes that, the stale mapping labels (Astra M2), one label (Muse M6) and the revocation wording above (Astra M4, Muse M2). The other Minors are in deferred.md.

### Changes

- **Playback latch.** Before this, one failed Current-edit acquisition set `studio.failure`, and the start gate waited for that to clear, so playback never retried. The failure is now tied to the scope it was attempted on (`ManualFailure` in `studio.rs`). A newer scope clears it at once. A temporary failure (`HistoryChanged`, `Unsettled`, a lost reply) is retried at most 3 times on the same scope, after 2, 4 and 8 s. Each wait is longer than the heartbeat, so a newer scope arrives first. Any other failure waits for a newer scope. There is still one acquisition job per attempt, not one per frame. `open_current` now types the host's refusal codes, so `history_changed`, `unsettled` and `save_in_progress` stay temporary.
- **Mapping labels.** A Current-edit mapping now records the saved checkpoint it was mapped onto. The host reports that checkpoint in `HostStatus.manual_checkpoint`; with no host, the App reads it from the session. Notes maps the notes again when the checkpoint changes, and drops the mapping when the target changes. Before this, the mapping was dropped by playback scope, so a clip move and a Save kept the old label. While the edit has unsaved changes, Notes says: "Places are on the last saved edit. Save to place them on this one."
- **Transformed label.** The App does not draw the mapper's proposed points (C10 deferred row "proposed points across strokes"). `SpatialStatus::Transformed` now reads "picture changed, drawing may not line up" instead of saying the drawing moved.
