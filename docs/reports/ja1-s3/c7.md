# JA-1 S3 C7

C7 sends Revise cut to the S4 scheduler through the writer host. Notes shows each batch's run.

- **`HostCommand::ReviseCut { request }`** (`writer_host/revise.rs`), owned by S4.
  - It takes the submitted batch's retained `ReviseRequest`.
  - It forks a candidate branch from the manual head.
  - It admits a plan and a Director assignment that name the batch and the exact request.
  - The Director comes from the person's scheduler setting (`scheduler/director.json`). Its scope is the whole document at the candidate.
  - The run publishes through `dispatch_orchestration` with `consume_batch`. The batch consumption and the RunIndex entry land in one root publication before `Accepted`.
- **Replay** comes from the command id.
  - A consumed batch answers with its run only when that run's Director assignment names this exact request. Otherwise it returns `batch_consumed`.
  - The same command id with a different batch or head is `id_payload_conflict`.
  - An uncertain earlier publication resends its original envelope.
- **Results.**
  - A moved manual head is `Conflict`.
  - No Director, or no free run slot (64), is `Waiting(reason)`, and the batch is not consumed.
  - An Editor, the role that may already start a run, starts it.
  - A Viewer gets `Waiting`: the notes stay durable feedback.
  - A Producer is refused.
- **App** (`studio_feedback.rs`).
  - After a durable SubmitBatch, the request is kept on disk (`Kept.revise`) before ReviseCut is sent.
  - An unknown reply, a transport error or a restart resends that exact request.
  - Notes shows Accepted, Waiting(reason), Conflict or Refused.
  - A batch that has no run and no kept request offers Start run.
- **Run state in Notes.**
  - Each batch row shows its note count, a hover list of its revisions, and the linked run's phase, outcome and wait. These are read from `ObserveRun` and polled once a second until the run finishes.
  - Observing touches only the rows. It never changes the selection, thaws producers, or labels anything Delivered.
- **Host-attached reads.** `ReadFeedback` returns the note's text and strokes evidence under the same pin, because the App has no reader store while the host holds the bundle. `Ja1Attachment::project_identity()` keeps the project id across the host handover.
