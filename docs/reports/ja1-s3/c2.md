## C2 regression repair

This repair follows the accepted thumbnail fix `39589b56` on `ja1/s3-c2fix`.
It addresses regressions introduced by C2 (`ed23d49a`), whose parent is

### Root causes and fixture decision

C2 made `clear_preview` clear the focused project's retained CPU frame.
`close_project` removed a project before updating `focused_project`, then
called preview cleanup through the focus rebind. Closing the last, focused
tab therefore indexed past the shortened project list. Removing a tab must
update its selected index before any subsequent code uses that index. The
eight existing IN2B save, reopen, focus, and recovery tests remain unchanged.

The Linux Studio-owned colour fixture stopped polling when the imported asset
first appeared. C2 added certified manual-playback admission at the end of
`poll_background`. That asynchronous operation temporarily moves the local
attachment into `ja1_job`; `poll_ja1` returns it to the UI when admission ends.
The original fixture's finish function immediately accessed `ja1`, so it raced
this new admission. A diagnostic run of both unchanged colour scenarios reports
`attachment=false admission_job=true manual_inputs=false failure=None` before
their existing unwrap fails. Its summary is 0 passed and 2 failed; the failed
process also reports SIGSEGV during teardown after the panics.

The asynchronous production behaviour is required to admit certified inputs
without blocking the UI. Before changing the fixture, the decision is to wait
for the imported asset, completed admission, returned local attachment, and
certified manual inputs. This strengthens setup readiness. It preserves every
existing check that the colour fix never reaches Core unstaged, leaves the
incident open, and keeps the saved history unchanged and saveable.

`git diff 7f73f9c8 ed23d49a -- crates/kinewright-media/src/decode.rs` confirms
that C2's new `open_certified` copied the `MediaError::SourceColor` constructor
from `open_managed_threads`. The two decoder entry points must share the same
managed-source admission and declared-depth validation. The IN1 single-site

### Authority keys and retained state

`LegacyMediaIdentity` names one issued grant. `PlaybackAuthority` retains one
certified namespace identity, including across `PlaybackInputs::with_document`.
`VideoSourceKey` includes that authority. The scheduler's existing complete-key
comparison now partitions assignment and keeper affinity without another
per-assignment predicate.

- `VideoSourceKey` includes an immutable `LegacyMediaIdentity` or the retained certified namespace token. `Readers<K>` uses the complete key for free-slot assignment, keeper affinity, source regions, rings, errors, pending plans, refill windows, reservations, retained-frame charges, travel history and frame-size memory. `SuppliedFrames`, synchronous renderer decoders and working-frame caches, preview demand points and compositor video residency use that same key.
- `SourceSpec` captures the originating grant. A reader holds its grant's work lease until its native thread has joined. Revocation has no wakeup, so idle readers and permit waiters poll for it every 50 ms, and an idle preview prunes exited readers at the same interval without running GPU maintenance early. A detached thread transfers its join and lease together to retirement work, so timeout does not manufacture quiescence.
- Each video decoder's retained decoded frames, lookahead frame, conversion context and demux shadow remain inside its authority-bound reader or renderer entry. Retained conversion enters the captured grant again. Every ordinary decode retry and shadow packet lookup checks revocation.
- `Rendered` and the playback `Held` frame retain the originating `Scene`, including its grant or certified namespace. Publication enters that grant and refuses a revoked frame.
- The coalesced active-document binding compares `SceneAuthority` as well as the document allocation. Equal `Arc<Document>` values cannot preserve another session's authority.
- Live audio retargeting retires the old runtime on an authority change. Mixer source PCM, mixer DSP state, runtime pending PCM and the output ring retain their originating grant. Refill and conversion enter it. Native and simulated output callbacks check that grant before consuming retained samples. Lazy audio decoders already capture their grant and reacquire it for each chunk; `DecodeInput::check` now checks active locator scope too.
- Transcript, silence, scene and beat status caches, duplicate-job suppression and cancellation registries use `(LegacyMediaIdentity, path)`. Whisper progress callbacks retain the same metadata authority across callback threads. Status metadata has a 4096-entry cap.
- Waveform and asset-thumbnail in-flight jobs use `(LegacyMediaIdentity, JobKey)`. Their bounded result channels are per authority, with a 64-authority registry that discards revoked entries and refuses overflow.
- The App timeline visual cache binds its whole instance and result receiver to `LegacyMediaIdentity`. Switching authority or revoking it discards waveform data, thumbnail textures, pending/failed request sets, LRU/accounting, blocked paths and path generations. Revoked sessions return no visual-result stream, so queued old results cannot refill the cleared cache.
- Serialized waveform, thumbnail, transcript, silence, scene and beat cache files stay content-addressed and are not keyed by authority. A lookup needs the file's SHA-256, and `ContentHashes` always recomputes it through `sha256_file`, which opens the locator inside the requesting job's lease. A hit therefore serves only bytes the requesting grant has just read. The result is a pure function of those bytes and the recipe configuration. An earlier draft of this fix prefixed the filenames with a per-run grant namespace. That prefix was dropped: it would have stopped transcripts being reused across launches without closing any additional path.

An agent thumbnail rendered inside a suspended paused wait restores the renderer's previous authority afterwards, so the resumed frame looks up its own supplied frames. Generated title and solid rasters come from document text, not locator bytes, so they are not partitioned. An earlier draft of this fix cleared the whole renderer on every grant change; that was dropped as redundant with the keys. Verified LUT lattices and model weights contain no project media; their existing content-bound caches remain shared. The C6 Current-edit manual cache and acceptance follow-ups remain outside this brief.
