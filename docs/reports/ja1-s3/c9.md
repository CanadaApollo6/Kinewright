# JA-1 S3 C9 host snapshot leases and Studio voice

`LeaseSnapshot` authorizes like ReadSnapshot and pins the selected descriptor's complete transitive graph: checkpoint, document, lineage, input manifest, revision references and certified media. Attachment-owned random ids bind the descriptor and graph digest to the host epoch. Leases end on release, successful project/owner transition, attachment end or host death; a failed transition preserves them. Held pins block named-writer retirement and survive collection.

The App opens immutable objects through an unclaimed read-only namespace, without a writer or conflicting lock. The host keeps physical storage charges; one App attachment shares bounded graph metadata and decoder budgets. Each object is hash-checked before exposure. FrozenContext and SessionMedia carry the lease-bound revocable authority through resources, certified inputs, cursors, native decoders, playback and cache hits. The visual reader cannot read private voice evidence. Reader close releases its lease; attachment close revokes all readers.

Studio now captures at the bound picture through the feedback recording destination, shows ASR progress, edits and chooses a transcript, saves a voice revision and submits it in the existing immutable batch. The App retains capture files until acknowledgment and performs receipt-first recovery; uncertain transcript choices retain their original envelope. Whisper stays in the host for C5 completion ownership and retry, with the shared one-model mutex and pinned ensure_model path described in c8.md.

The actual App composition exposed two additional host boundaries: blocking retention callbacks must run outside the async HTTP handler, and voice feedback commands use the existing comment lane while an Editor holds manual access. Typed feedback reads and host-reported durable project identity let attached Studio save/read feedback without borrowing the GUI's retired store. No ReviseCut scheduler or Notes run-state behavior changes.
