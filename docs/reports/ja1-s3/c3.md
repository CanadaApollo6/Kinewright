# JA-1 S3 C3

C3 adds typed and drawn comments in `kinewright-app/src/studio_feedback.rs`, with the host feedback adapter.

- **Capture** reads only the bound display cell, never the pending selection or seek. It records the version, or the exact manual cut, plus the frame, rational fps, raster, orientation, text and strokes. Strokes are normalised against the displayed image rectangle after letterboxing. The target stays unresolved until the person picks a layer. Source and beat stay absent.
- **Frame proof** carries the bound cell identity. On the CPU route it also carries a SHA-256 of that cell's own pixels, hashed on a thread that owns the image it started on.
- **Manual-edit drafts** are promoted only when a published snapshot's checkpoint history has the identical document and journal position. A newer head never promotes them, even after an undo back to the same document.
- **Save** clears a draft only on a durable receipt that the index retains. A refusal or an unknown outcome keeps the draft, and the retry resends the exact original command.
- **Revise cut** sends a batch of exact revisions, which can mix versions. A retry resends the original batch whatever the selection became. With no scheduler attached, the state reads "Submitted · waiting for a run".
- **Edits** to a saved note create a new revision with the original anchor and proof reference.
- **Caps** refuse at ingress and keep the draft: 2,000 comments, 16 KiB of text, 512 points.
- **Host commands.** `AdmitFeedbackEvidence` stores bounded evidence. `ListFeedback` returns the private index. The Producer role is refused both.

## Fix 1

Fix 1 closes Astra's three Majors (Muse M1 and M2) and the in-scope Minors.

- **Typed or drawn feedback is never lost silently.**
  - A draft the person typed or drew, and an unconfirmed Revise cut request, count as unsaved work. They mark the project dirty and appear in the close and quit warnings.
  - Drafts, every in-flight command and the selection are kept on this computer in `Kinewright/feedback/<stem>-<fnv64>.json`, beside the recovery journals. The file is written atomically.
  - A save or submit is written there before it is sent. After a restart, the draft comes back pending, and the app retries that exact command once: same envelope, same batch id, same revisions.
  - A kept file that cannot be read is left untouched, and the warning says closing discards the notes.
- **A manual draft is promoted only by its own cut.** The cut binds the accepted branch and a SHA-256 of the whole history snapshot (baseline, every batch, cursor). Capture also requires that no core event is still queued, so the exported history is the one on screen. The head is not bound: an unpublished cut has no head yet, and the history digest is stricter.
- **A stroke belongs to one bound picture.** A drag records the bound frame id when it starts. The first point over any other picture ends the stroke and tells the person why. A failed capture starts no stroke, so no point can land on a pending draft.
- **Minors.**
  - Editing a revision keeps its strokes evidence, `voice_ref` and `transcript_revision` unless the person changes them (Astra 4, M9).
  - The selector lists the exact selected revisions, older ones marked, with Use newest and Remove (Astra 5).
  - New note is a Notes button and Alt+M. Alt+N stays with the composer (Astra 6).
  - `SaveFeedback` refuses a frame-proof reference that is missing or larger than `FRAME_PROOF_BYTES` (M5). The owner does not parse the proof: S2-era store fixtures save raw-byte proofs, and Muse asked only for the dangling and size backstop.
  - Submit success requires the batch in a fresh index read (M8).
  - In a narrow window, the Revise cut bar scrolls with the list instead of covering the draft card.

## Fix 2

Fix 2 closes the five data-loss Majors from Astra's re-check of fix 1, and the in-scope Minor. Four Majors came from the path-keyed sidecar. That design is replaced as a class: kept feedback is now keyed by and checked against the project's durable identity.

### Where kept feedback lives, and why

Kept feedback is a per-user state file named by the project's `ProjectId`:

- `LOCALAPPDATA/Kinewright/feedback/<project-id>.json` when `LOCALAPPDATA` is set (Windows, and the test harness);
- otherwise `XDG_STATE_HOME/kinewright/feedback/`, then `~/.local/state/kinewright/feedback/`.

The folder is created with mode `0700` and the file with mode `0600`. The file is still written atomically. `kinewright_project::feedback_state_directory` refuses a location under the temporary folder, or on tmpfs or ramfs. With no per-user folder at all, it refuses too. In every refusal case, nothing is sent and the warning says closing discards the notes.

Kept feedback does not go inside the project because of how the owner checks commands. Every metadata command carries `expected_root_generation`. Writing drafts through the owner bumps the generation, so the pending command that the draft retains would then be refused as `HistoryChanged`. Storing drafts in the bundle would also need a new owner protocol, rules for copies, and a decision on who may read private drafts. The brief allows a sidecar under four conditions, and this design meets each one:

- **Persistent per-user state.** The file is never under `temp_dir`, and its permissions are private.
- **Identity checked first.** The file carries its `ProjectId`. Every merge and retry checks that id, and each restored command's `envelope.project_id`, before anything else.
- **A mismatched file is kept separately.** A file that names another project is renamed aside whole (`<id>.json.other-<their-id>-<pid>`) and is never merged.
- **Migration is defined.**
  - A rename or move keeps the `ProjectId`, so the same file is found.
  - Save As mints a new id. The old project's state is written first, and its in-flight commands stay in its own file. Unsent drafts and the selection carry over to the new project, and the cached issuer is reset.
  - If the old file cannot be written, nothing is dropped. Pending drafts carry over as unsent drafts, and an unconfirmed batch's notes go back into the selection.

Residual risk: a copy made outside Kinewright keeps its `ProjectId`, so both copies share one file. Restored drafts can then appear in both. A retried command is still checked by the owner, and draft content is never deleted, but one note could be saved into both copies. Fix-1 kept files (`<stem>-<fnv64>.json`, v1) are ignored; fix 1 was never merged.

### Invariants

- **No dispatch without durable retention.** Saving and submitting go through `retain_for_dispatch`:
  - an unsaved project, or one whose kept state failed to load, refuses with a named reason;
  - for a kept project, the exact command is written before it is sent.

  A file that cannot be read or parsed leaves the project in `Keeping::Failed`, and nothing is written over that file.
- **Replay must match its draft.** Before a restored pending command is retried, `command_matches` checks:
  - the comment id;
  - that the command is `SaveFeedback`;
  - the text digest and length;
  - the strokes digest, or the original strokes reference when the strokes are unchanged;
  - the frame-proof digest and the anchor rebuilt from the proof;
  - the voice and transcript references.

  On a mismatch, the command moves to `detached`, where it is retried exactly until its outcome is known, and the draft stays as a separate unsent draft. A new save of that comment first settles the detached command. A kept submission whose batch differs from its command's batch retries the command's batch. The differing kept batch's notes stay in the selection. A command that does not match its own request is detached.
- **No drawing on a restored draft by frame-ID match.** `Draft::live` is set only by a capture in this run and is never kept. A new stroke captures afresh unless the active draft is live and shows the same bound frame. The overlay paints only live drafts.

## Fix 3

Fix 3 closes the one Major in Astra's round-3 re-check. Two copies of a project with the same `ProjectId` each wrote their whole in-memory state to the one kept-notes file, so the later writer removed the earlier one's note.

### One live owner per file

- `kinewright_project::lock_feedback_state` takes an exclusive lock on `<project-id>.lock` beside the state file. It uses `flock` on Linux and `LockFileEx` on Windows, through `fs2`, on a handle of its own. It never waits, and the lock file is never removed.
- `Feedback::open` takes the lock before it reads, merges or sets aside the file. The lock lives in `Keeping::Kept` until the identity changes or the session drops. On an identity change, it is released only after the old file's last write.
- A second owner in the same process or another one gets `Keeping::Failed` with "This project's notes are open in another window". It never reads, sets aside or writes the file. It refuses Save note and Revise cut with that reason, and its close warning says closing discards its notes. A lock that cannot be taken at all refuses the same way, with that error named.
- The second owner is not promoted when the first one closes. It must reopen the project to take ownership.
