# JA-1 S3 C10

C10 adds two things. The person chooses the Director in Settings. A start-to-finish Studio test drives the real App, host, store and media while host-attached.

## Part A: the Director setting

- **Offered list** (`orchestration/adapters.rs`). `certified_connectors()` is the one list of certified connector profiles. Certification registers each shipping profile there. None is certified yet, so a shipping build offers no Director. Builds with `cfg(test)` or the `eval-harness` feature also certify the scripted fixture Director (`scripted · fixture`). No shipping launcher can start it. Release builds use `--no-default-features`, so they offer nothing.
- **Setting** (`orchestration/director_setting.rs`, owned by S4, re-exported by the writer host).
  - `director_choices()` maps the registry. Nothing else can be chosen.
  - `director_status()` reads one file of at most 16 KiB. The status is one of these: `Set`, `Missing`, `NoLongerOffered` (a choice this build no longer certifies) or `Unreadable`. Reading starts no provider, probe or network call.
  - `write_director_setting()` refuses a choice that is not offered. It writes a temporary file, syncs it, renames it over `director.json` and syncs the folder. An unreadable file is replaced only when the person chooses again.
  - `revise_cut` reads the file on every Revise cut through `configured_director()`, so a change applies to the next run. A run that has started keeps its provider in its `TaskBrief`. Missing, no longer offered and unreadable all answer `Waiting` with a plain reason, and the batch stays unconsumed.
- **App** (`settings_ui.rs`). A DIRECTOR section sits above the Investigator section in Settings. It reads the setting when the window opens and shows one provider and model choice, plus a muted status line. With an empty list it shows only "No Director is available on this computer yet. Your notes still save." It uses the current theme tokens; PO0's settings step has not landed.

## Part B: `s3_studio_end_to_end`

`crates/kinewright-app/src/studio_e2e_tests.rs` (Linux) runs one App, one child writer host, the project store and real fixture media. Two published versions differ by clip speed: A (100%) and B (200%).

1. **Moment and delayed A/B.** The App shows A at frame 2, then selects B. B's preview is held behind A's pending completion and delivered late. While B is pending, the picture, its fence and its identity stay A's.
2. **Notes.** A drawn note is made with the stroke API while B is pending. It anchors to the shown A at frame 2, on the chosen layer's occurrence. Then the App seeks B to frame 4 and records a spoken note. The person edits its transcript and chooses it.
3. **Mixed-version batch.** A first proxy drops the `metadata` reply, so the batch status is Unknown. The retry resends the same bytes. A second proxy drops the `revise_cut` reply. Then the kept request settles. The submitted batch pins anchors on both A and B, and the voice note is on B. The transcript revision's SHA-256 is the SHA-256 of the chosen text.
4. **Revise cut.** The Director is chosen through Part A's `choose_director` path. Revise cut is Accepted, Notes links the run, and `ObserveRun` shows the chosen provider in the brief.
5. **Notes on an edited copy.** The notes are mapped onto B. Then the App opens "Edit a copy" of A, makes an edit through the host's manual gate (a new audio track) and saves it, and maps the notes onto the current edit through `ResolveFeedback`.
   - The drawn note is `Exact` at frame 2 on the copy and `Mapped` on B.
   - The spoken note names no clip, so it stays `Unresolved` rather than guessed.
   - Notes shows "Find in this version" and "Find in current edit", with one label under each saved note.
6. **Close and reopen.**
   - Close keeps the pending run: the host detaches to continue it (`DetachForContinuation`). While it runs, opening the project is refused with `Contention` (`E2E_LIVE_ELSEWHERE`).
   - No connector is certified, so the run never ends by itself. The test ends that detached host process, its own child, by exact pid. This stands in for the run ending; only durable state comes back.
   - A new App and a new host reopen the project. The versions, the three notes (text, strokes evidence, transcript), the batch, its linked run and the recomputed mappings are unchanged. A replayed Revise cut returns the same run.
- **Save As.** Save As gives the project a new identity, and notes typed after it are filed under the copy. A's kept-feedback file is byte for byte unchanged.
- **Final check.** The original project holds exactly one run.

## `ResolveFeedback`

`HostCommand::ResolveFeedback { revision, onto }` (`writer_host/resolve.rs`) is read-only.

- `onto` is `Version { key }` or `CurrentEdit`. The host chooses the checkpoint: the published snapshot's checkpoint, or the manual branch's current checkpoint.
- It has the same roles as `ReadFeedback` (Producer refused). It uses the same pins, and repeated pins are deduplicated. It counts toward the 64-pin attachment cap.
- It returns `FeedbackMapping { resolution, candidates, original_frame }` from `ProjectBundle::resolve_feedback`. Nothing is stored. G10 and §7.2–7.3 ask for a lead disposition, not a stored resolution record, so reopening recomputes each mapping.

## Findings fixed in C10

1. **App captures named no occurrence.** `Layer` had no occurrence, so every App note's anchor had `occurrence_id: None`. Every mapping was Unresolved, against §7.2–7.3. Capture now fills each layer's occurrence from the shown version's lineage. Host-attached, it reads through the snapshot reader.
2. **The mapper could not read App strokes.** The App writes strokes (`[[[x,y],…],…]`) and the mapper parsed flat points only (`damaged_bundle: invalid type: sequence, expected f64`). It now reads either form (`c10_drawn_points_reads_points_and_strokes`).
3. **Busy loop on the Current edit while host-attached.** `StudioManualPlayback` returned `HistoryBarrierInvariant` from `studio_playback_scope()` through `?`. It never reported the failure, so `sync_studio_selection` started a new job thread every frame. This existed before C10. Every failure is now reported once ("Playback input unavailable: …"), and the Studio stops asking (`E2E_NO_RESPAWN`).

## When Current-edit playback is unavailable

Whenever a host holds a **saved** project, from the first frame after launch. "Edit a copy" is not needed; it was only where this test first looked at the Current edit.

- `Ja1EditingSession::prepare_host_attachment` (`editing_session.rs:367`) hands a named bundle to the host. It calls `release_named_writer_for_host`, then sets `self.destination = None` (line 429). A project opened from disk has no session source either.
- After that, `Ja1EditingSession::store()` (`editing_session.rs:1140`) returns `HistoryBarrierInvariant`.
- `launch_host` calls `start_host_manual` right away, so the attachment is writable. With no frozen selection, `sync_studio_selection` (`studio.rs`) starts `Action::StudioManualPlayback`. That calls `Ja1Attachment::studio_playback_scope()` (`ja1_attachment.rs`), whose `self.owner.store()?.owner_epoch()` fails. `manual_playback_inputs` would need the same store.
- A probe (a temporary test, removed afterwards) launched a host on the saved fixture and stayed on the Current edit, with no copy made. Output: `read_only=false`, `scope=Err(HistoryBarrierInvariant)`, one manual job, `failure=Some("Playback input unavailable: internal_history_barrier_invariant")`. Before the C10 fix, that one job would have repeated every frame.
- An **unsaved** session keeps its session source across the handover (`retain_borrowed_source`), so the scope resolves. The session is read-only until First Save, so no playback request is made. The probe's host First Save stopped on a fixture limit ("retained asset media:1 lacks exact fingerprint"), so the state after First Save was not observed. By code reading, `retire_ordinary_copy` drops the source once the copy becomes the named destination, unless borrowed sources remain, so it then matches the saved case.

So in normal agent use, a saved project with its host attached, the Studio cannot show the Current edit. Frozen versions play through C9's lease.

## Not covered

- **Current-edit playback while host-attached.** Unavailable whenever a host holds a saved project; see the section above. No host port admits the working branch's playback inputs. The Studio now reports this once, and the test edits and maps without a picture. Destination: C11 inside S3, a current-edit playback port beside C9's lease (lead, 2026-10-29).
- **A live Director.** No connector is certified, so `certified_connectors()` is empty in shipping builds. The separate certification item before S5 owns it. "The next run uses a changed provider" cannot be shown with one certified profile.
- **Settling a run before Close.** Close detaches the host to keep a pending run. Notes has no Stop (C7 deferred row), so the test ends the detached host itself.
- **The voice upload's unknown reply.** It cannot go through the JSON reply proxy, because the upload is a streamed body. C8/C9 fix 1 covers it (`fix1_pre_ack_capture_reopens_and_retries_same_bytes`).
- **Rescue copy in the same App.** It is covered by the C1/C6 rescue tests, not by this test.
- **Physical microphone, Windows, hosted CI, review rounds, push.**
