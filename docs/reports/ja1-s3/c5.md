## Fix round 3

Every public `SaveVoice` command now enters the note's owner-held slot. `ProjectBundle::metadata_command` routes voice writes there, so the existing WriterHost dispatch uses the same coordination. The metadata implementation is private. Its voice entry requires a capability whose constructor is private to `voice_store`. The slot's own publication uses that capability while already locked, without re-entering the public router. Raw metadata notes use a slot without capture state until a capture view opens the note.

A pending ASR or exact pending command refuses a direct voice write with `Unsettled`, including a direct write of the same original. A view settles the retained command. A definitely refused transcript choice permits a newer direct choice, but retains the choice it originally expected. Retry compares that expectation with the durable note. A conflict clears the stale pending choice and its pin, refreshes the view, and reports `HistoryChanged` without replacing the newer choice.

Once taken, a ready completion belongs to the owner-held pending state through admission and publication failures. The App wrapper preserves this contract. The native control's caller keeps one completion and retries contention without another inference run. `start_job` also refuses while the shared job is active. Accepted and cancelled jobs remain restartable.
