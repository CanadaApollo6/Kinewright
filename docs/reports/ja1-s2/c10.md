## Result and authority

Host failure freezes the GUI actor before draining submitted work. The successor resolves the unchanged original command IDs/digests against the acknowledged root. It replays only the proven-absent contiguous suffix on the shadow, under fresh recovery authority, with every original-to-new receipt and original BatchId in one ordinary bounded root publication. It preserves the original open gesture until full accepted-history equivalence. Committed commands are reconciled without reapplication. Unknown, conflicting, retired-unresolved or replaced-parent evidence pauses recovery.

An ordered floor uses the ordinary S1 selector and overlap reservations. Both actors install and confirm the same exact durable result before recovery-close; both then install/confirm the recorded close before a fresh lease. An automatic floor selected while publishing an absent suffix is carried through the same handshake. Lost floor/close replies retry the immutable envelope and exact recorded result through another real process restart. Empty acknowledged prefixes use an absent command cut.

The App worker performs restart and IO off the frame thread, borrows the same actual GUI source admission, and cannot retire its source pins, bytes or charges. Resume and fresh-permit binding occur in one actor turn while the originating context is open. Unrecoverable retained-destination/prepared-selection ownership refuses. Rescue own-ticket settlement remains separate. Dirty/unsaved host bootstrap remains read-only until explicit Save.
