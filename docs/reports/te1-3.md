## TE1.3 completion and commit scope

The feature is a separate new commit above the merge. No TE1.3 production
change is included in the merge commit.

`finish_task` accepts a task id and the observed timeline revision. Its first
ordinary H1 transaction stores the outer command identity, logical request
digest and original attempt. The host accepts completion only for a work turn
with settled children and deliveries, no pending question and no background
work. An unready request cannot reserve the parent's settlement identities.
Freeze and publication use the same issuer's next two identities. The host
reserves those identities on every public task Producer route.
An original substep receipt is reused before constructing any new envelope.
Each missing substep separately passes current attachment, endpoint, epoch,
grant, scope and ordinary-write admission. A receipt or completion status
never grants mutation authority.

The task's ingress gate drains before the freeze revision check. A later edit
cannot silently rebase the accepted completion. Publication uses the exact
frozen result and the existing host-owned accounting-reference binding.
Completion phases are freeze -> publication -> parent delivery -> settled.
A freeze alone is pending or blocked. Publication without applicable delivery
settlement is pending; only durable publication plus the parent's authenticated
observation, when required, is completed. Disposed delivery is blocked.
Substep failure retains the original successful outer intent outcome and
reports progress outside that immutable outcome. A failed progress read also
retains the acknowledged receipt and returns an explicit blocked/unavailable
status; it cannot replace the original outcome with a refresh error.

Live retries reuse original receipts and results. Stop or restart cannot revive
a task endpoint. Foreground reconciliation binds the original project, run,
task, attempt and command digest, and reads the retained facts without writing.
Trusted production reopen derives an explicit person-review block for an
unfinished completion or before-commit merge. It retains the frozen work and
manual merge envelope, disables Continue and refuses reservation/charging of
new native sends. The person must Stop and review before starting another run;
this implementation does not automatically merge after reopen. The new crash
witness uses the production restore and reservation paths, not the old private
merge-completion test helper.

Accepted edit-plan commits return the actual committed revision and a
conservative affected scope: operation names and JSON pointers derived from
the exact before/after document. Collection-size changes cover the collection;
projections exceeding 256 paths or 16 KiB cover the document root. A reporting
limit cannot turn an accepted commit into an error.

The role manifests append `finish_task` for Director, Editor-family and
Reviewer tasks. Their explicit schema goldens change; unrelated compact tools,
capability registry, instructions and full-wake goldens remain pinned. No
context/prefix rewrite, specialist setting, provider registration, terminal
capability, spending limit or accounting normalization changes are included.
