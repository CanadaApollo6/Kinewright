## Behaviour and boundaries

The application prompt and every result wake begin with fixed instructions, the durable role, the role manifest identity and the fixed context contract. Variable live controls, task identity, brief, note references, overview and payload follow that prefix. Codex and Claude protocol fixtures receive the identical application prefix and manifest. These are application byte measurements; provider request ordering, subscription cache hits and model decision quality remain unobserved.

A task starts with an overview bounded to 8 KiB. It names timebase, duration, track roles, linked/ripple relationships, caption boundaries, note anchors and available/omitted evidence. Large overviews explicitly omit fields and give a classified expansion request. Timeline expansions include their link, ripple, neighbour, caption, sync-group and audio-routing closure, and the note/evidence catalog. Cursors bind the run, task, actor revision, document digest, request and exact data being paginated. Oversized rows use fixed UTF-8 JSON fragments with row digest, length and offsets, so all facts remain recoverable without an unpageable row.

`read_task_evidence` accepts typed timeline, reference, transcript, audio, frame, preview and proof requests. Transcript spans accept admitted word arrays or saved UTF-8 voice transcripts (whitespace word boundaries and unknown alignment), include two neighbouring words on either side, and include a source dependency read; missing source alignment is explicit. Media reads lease only the task's owned input manifest and return bounded samples with partial coverage and unobserved exact seek alignment. They release the owner lock before decoding, drop decoder pins before reacquiring it, then recheck live authority and actor revision before recording or returning the read. Video row padding and inactive audio samples are excluded; planar audio channels are interleaved from initialized typed planes, with a real silent-left/non-silent-right AAC witness. Samples support up to eight channels; unsupported layouts refuse. Unsupported or unavailable streams refuse.

Each returned expansion records a host-owned ordinary `RecordContext` decision before replying. The durable task projection enforces eight expansions across reconnects, with no terminal-admission shortcut. Every complete MCP page is at most 24 KiB. Exhaustion returns the fixed `evidence_capacity` refusal: “Evidence capacity exhausted; replan without guessing.” Read context never changes the task's edit policy or scope.

All six role manifests include classified evidence reads: Director for coordination, Editor/Motion/Audio/Colour for decisions within their existing edit scopes, and Reviewer for read-only review. Only Director exposes `read_child_result`. It binds the authenticated parent, child, run, exact terminal result and source checkpoint binding, and paginates full explanation, delta, accounting and retained history. The existing `read_task_result` retains its reference-only request shape, its own/child-result authorization and bounded ordinary read audit. Sibling and unrelated references remain refused.

Wakes disclose outcome, partial coverage, satisfied/unmet/expected note IDs, conflicts, proof status/failures, changed scope, omitted changes, revision kind (`checkpoint_head`), base/head, evidence/proof references and the exact detail request. Unclassified reports remain unknown. Summaries retain rejection facts; oversized disclosures name omitted fields and counts and require expansion before acceptance. Full merges still validate the exact durable result and history, independently of a summary or reported proof success.
