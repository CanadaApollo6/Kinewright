## What landed

The project-owned `orchestration_records.rs` defines versioned, serializable
run snapshots, immutable event segments, effects, requests, deliveries,
results, usage, and native reservation identities. It reuses existing project,
command, branch, head, digest, object, and validated UUID identities.

`orchestration_commit.rs` validates complete proposed cuts and their dependency
edges. Receipt validation binds the original envelope, including project,
command, task or run scope, target/base refs, epoch, control precondition,
payload, and hashes. The reservation-loser path and final returned cut have
separate checks. Deterministic refusals and unresolved receipt states remain
distinct. The H1 adapter must use the existing shared issuer and receipt ledger.

Agent `orchestration/{mod,machine,outbox}.rs` supplies pure decisions and folds,
stable scoped identities, control-revision refusal, ordered claim proposals,
process-bound uncertainty, and a single pending publication that freezes
scheduling until exact-envelope reconciliation. C3 and C4 commands remain
unsupported here. No provider, native child, alternate writer, or database is
started.

`ExecutionIdentity` and `AttemptReservation` freeze the C2 identity contract.
Opaque, nonserializable `AdmittedAttempt` has no public constructor. Its owner
hook checks the exact Applied receipt and reserved identity before returning
launch permission. The H1 production caller is absent. C2 retains responsibility
for OWNED, CONTAINED, COMMIT, the machine claim, and native cleanup proof.

The agent module is registered. The project modules are compiled from their
exact owned sources through temporary agent path declarations until S3 registers
them. No S3-owned file was changed. Guardian and claim modules will be registered
when C2 files are integrated. The later C2 handoff assigns their module and
manifest registration to A; no such manifest change is needed in C1.

## Isolated witnesses

`kinewright-project/tests/ja_s4_store.rs` exercises the complete proposed cut,
exact replay receipt, forced concurrent reservation loss across different
payloads and projects, pending graph refs, unsupported versions, original
digest binding, stale generations, and mismatched events. Its nine tests use
isolated contracts. The in-memory receipt race does not exercise the actual
sealed publisher.

`kinewright-agent/tests/ja_s4_kernel.rs` exercises deterministic task/effect
identities, control revisions, exact ordered effect claims, unknown external
outcomes, safe reconciliation, original-envelope publication freeze,
reservation proof admission, and Stop with retained cleanup and provider wait.
These are pure kernel tests, not native or durable runtime witnesses.

The store suite also checks event predecessor retention, unique attempt IDs,
aggregate cleanup consistency, and large owned-media references without treating
media byte length as decoded control-record size. It contains nine tests.

All 12 protected contract mutation pairs produced a literal runtime red and
restored green. [c1-mutations.json](c1-mutations.json) records the witness,
source hash, and raw summaries for each pair. The guards are reservation scope,
final returned cut, pending effect edge, schema support, original digest,
unknown-publication freeze, no claim reclamation, reservation identity, refused
attempt admission, predecessor retention, attempt uniqueness, and cleanup facts.
Their individual `mutation-*-red.log.gz` and `mutation-*-green.log.gz` files retain
the assertion failures and restored summaries.

[c1-identities.json](c1-identities.json) binds the final source artifacts and
test binaries to the recorded summaries. All five mutated source files match
their restored hashes. Binary hashes are retained; the local `target/` build
artifacts are removed after verification under the standing cleanup rule.
Only literal runtime failures followed by restored passes count. Compilation
failures, missing prerequisites, and zero-test runs do not count.

## Independent review

Astra at xhigh reviewed the isolated contracts. Round 1 returned CHANGES for
C1-R1, missing noninitial event predecessor edges; C1-R2, duplicate attempt IDs;
and C1-R3, aggregate cleanup contradicting retained attempts. Each received a
negative fixture and a separate protected mutation target. Event segments now
retain their predecessor, admission requires one reservation, and cleanup is
checked against every unretired attempt and blocked task. Ready cannot bypass
unretired attempts through a contradictory Settled aggregate. No findings were
declined. Round 2 returned APPROVE on the changed isolated contracts and marked
all three findings resolved. Its source-hash checks matched the mutation manifest.
Review usage was not returned. No review claims durable integration.
