## Landed behavior

The shared `kinewright-job-guardian` executable implements OWNED, CONTAINED, and COMMIT. It has no media or GUI initialization. AW2 will reuse this executable, per the lead's ownership ruling. No T3 Code source was translated for these native modules, so C2 does not import MIT-covered implementation. C1 owns the upstream notice registration.

Linux launches the guardian as the main process of an independent transient systemd user service. Its verified delegated cgroup-v2 payload leaf contains a native blocked shim before provider exec. The guardian is a verified subreaper. It kills through the retained `cgroup.kill` handle. The service uses whole-cgroup failure cleanup, no restart, a one-second stop timeout, and `TasksMax=64`. Transient units collect after retirement.

Windows uses `windows-sys = 0.61.2` behind the safe `kinewright-job-sys` API. An unnamed, non-inheritable, non-breakaway, kill-on-close Job has one owner. Process creation uses `PROC_THREAD_ATTRIBUTE_JOB_LIST` with `CREATE_SUSPENDED`, verifies membership and limits, then resumes only after COMMIT. The Windows control reader polls availability before reading, avoiding a pending empty synchronous read on the handle used for the pre-exec EOF check. Microsoft documents the concurrent synchronous-pipe hazard at <https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-peeknamedpipe>. Native Windows execution is NOT RUN locally. The native wrapper cross-check is a compile/lint lane only.

`DurableAttemptOwner` is the C1 integration port. `reserve` must acknowledge the durable attempt reservation before native launch. `authorize_commit` must persist the exact recovery identity and recheck current authority before COMMIT. C2's fixture supplies a private disk-backed acknowledgment, not a Studio root publisher. No project writer or driver event loop was added.

`MachineClaim::acquire` uses one OS-local namespace independent of project paths. Its non-inherited lock and bounded private records retain the original run, three admitted attempts, nonce, and owner identity. A free lock cannot reclaim unresolved execution. Recovery acquisition permits inspection and retirement, not new reservations. Native proofs bind the exact persisted recovery identity. Duplicate retirement refuses. Successful retirement removes the private guardian staging directory. Missing cleanup evidence retains the slot. Real Studio pins and charges remain the host owner's responsibility until that proof is accepted.

A failed startup commit closes the lifetime writer immediately, including uncertain or lost acknowledgment paths. Startup steps have five-second deadlines. An expired deadline refuses even an already-queued acknowledgment or COMMIT. Cleanup deadlines start at the kill decision, including time spent in the kill call, and the guardian records completion only from emptiness and reaping observations accepted within that window. `RecoveryObserver::wait_for_cleanup` starts a fresh two-second observation window on each call. A fresh complete independent observation can produce a recovery proof in that window. Cancel retains a 500 ms grace unless the complete tree is already empty/reaped. Host death skips grace. Whole-tree emptiness and required reaping must follow the kill decision within two seconds. Guardian loss disqualifies unsaved output. ## Lead ruling on §3 Linux deletion proof

The lead accepted deletion of the exact verified cgroup as independent emptiness evidence. This is not path absence, EOF, an unlocked claim, or an arbitrary failed query.

The observer opens and verifies the cgroup while live and retains its descriptor, device, and inode. If the events handle becomes unavailable during systemd teardown, only successful `fstat` on that descriptor with the same device/inode and `st_nlink == 0` proves deletion. Failed stat never proves deletion. Kernel cgroup removal requires no live members or child cgroups, and a removed group cannot admit new processes.

Deletion alone cannot retire a claim. A fresh complete `/proc` scan must find no live or zombie process under the old subtree, including paths ending in ` (deleted)`. The guardian and retained process identities must also be observed reaped. An incomplete sample retains ownership. A later fresh complete sample may establish proof within the deadline. Persistent ambiguity records `cleanup_blocked`.

The native signal witness records the kernel version and checks a positive live link count, zero on the same retained descriptor after real rmdir, and refusal to remove a populated cgroup. On this machine it recorded `kernel=7.2.8-10-omarchy live_nlink=2 removed_nlink=0 nonempty_rmdir=refused`. Unsupported kernel signals emit `C2_NATIVE_NOT_RUN` directly to stderr and write a reason file. The C2 gate refuses to count that lane as passed.

Kernel documentation supports the zombie/deletion distinction at <https://docs.kernel.org/admin-guide/cgroup-v2.html>. The report's acceptance is limited to the recorded native kernel and profile.

### Threat model and profile prerequisite

C2 contains the provider process tree against setsid, double fork and reparenting, cgroup migration outside the payload namespace, and Linux user-manager or session-bus launch requests through runtime-directory path sockets. The guardian and manager together retain cleanup responsibility for the complete service subtree. Claims retire only after verified emptiness and reaping.

C2 does not contain abstract-namespace sockets, persistence through the person's cron, at, autostart, shell or unit files, same-UID ptrace or signals against the host, or Windows WMI, Task Scheduler and COM launches. Those filesystem and IPC restrictions require C3 certified profiles. C2 alone is not a sandbox.

Both `ContainedSession::prepare` and `spawn_transport` require `CertifiedProfile`. Its fields are private and C2 has no production constructor. The only constructor is `cfg(test)`. Native integration tests compile the same production modules as a test crate to obtain that fixture token. A compile-fail doctest guards the public boundary. Provider execution remains unavailable through this API until C3 supplies certification. Existing pre-Studio drivers remain the deferred integration scope.

### Updated threat model

On equipped Linux hosts, C2 contains the provider process tree against setsid, double fork, reparenting, cgroup migration outside its namespace, and user-manager or session-bus launch requests through runtime-directory path sockets and proc-root aliases. The provider sees its PID namespace through fresh procfs. Cleanup and proof continue to use the host cgroup and proc views. Service emptiness, complete process observation, native identity and reaping remain separate requirements. A fresh later observation can establish cleanup after an earlier refused sample.

C2 still excludes abstract sockets, persistence through the person's cron, at, autostart, shell or unit files, same-UID host ptrace or signals, and Windows WMI, Task Scheduler and COM launches. Those restrictions require C3 certified profiles. C2 alone is not a sandbox. `CertifiedProfile` still has no production constructor, and provider execution through this API remains unavailable until C3 supplies certification.
