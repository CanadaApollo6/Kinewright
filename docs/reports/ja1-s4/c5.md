## Additive accounting records

`kinewright-project/src/orchestration_accounting.rs` owns version 1 accounting
records, admission, canonical registered encoding, and predecessor dependencies.
The existing `UsageRecord` and `RunProjection` shapes are unchanged. The existing
projection usage references retain the new typed accounting records.

The records retain requested and resolved connector, model, options, and CLI
version for each attempt. They retain known usage categories, partial coverage,
event identity, task-wide sends, configured token stops, provider waits, repair
counts, run start, deadline, and nondecreasing elapsed time. Waits and downtime
consume the six-hour allowance. Clock uncertainty pauses admission. Eighty sends
are shared across attempts. Two repeated failures across attempts require
replanning. Each delivery attempt has at most two automatic repair rounds.

Normalization distinguishes incremental and cumulative observations, refuses
conflicting duplicate identities, and preserves missing categories. Cache and
reasoning subsets are counted once. Missing incremental coverage remains
incomplete until a sufficient cumulative observation covers it. Late usage
retains a prior pause and can still be published. Token stops run after a turn
and retain one-turn overshoot. No monetary hard stop, paid fallback, automatic
model escalation, or provider quota is introduced.

`PreparedSend` prepares an immutable accounting successor and its registered
record reference. The owner-only acknowledgment port checks the exact committed
C1 cut, original envelope, task, active attempt, owner epoch, and accounting
reference before releasing a single-use permit. Fresh clock observation precedes
admission, and monotonic time also bounds the pending permit. Replay cannot
release another permit. This is an H1 receiving contract, not a second writer.

## Production ingress

Claude and Codex readers use a fixed 64 KiB pipe ring and reject oversized
frames before JSON deserialization. Encoded frames are admitted before any pipe
write. Stderr drains through bounded storage. The event queues hold at most 32
events, including reserved interruption and terminal slots. Ordinary parse
errors cannot consume those slots. Overflow interrupts admission and retains
previously accepted events.

ACP bounds its raw incoming queue, pending reply map, frames, and outgoing
encodings. Muse and the stream protocols bound unfinished tool identities.
Codex cleanup and terminal signaling match the original reader turn, so an old
reader cannot kill or complete a replacement process. Cursor configuration
leases and connector authentication code are unchanged.

`CommandQueue` admits at most 64 commands of at most 256 KiB. It reserves the
transient encoding through `ProjectStore::reserve_copy` before serialization and
holds dependency pins and that existing physical-ledger reservation until the
admitted command completes. Queue and encoding refusal leave accepted commands
intact. No second storage ledger is added. The existing graph, object, history,
metadata, receipt, and issuer limits remain the store owner's authority.
