## Raw adapters

- Codex 0.166.0 v1 uses cumulative thread usage. Input includes cache reads; output includes reasoning. Optional cache-write and reasoning categories remain unobserved without invalidating known inclusive input/output.
- Codex does not expose a per-helper model breakdown in this usage event. Its thread bucket joins to the host-selected model/options by attempt; actual helper/model attribution is unobserved. Claude retains every model explicitly reported in `modelUsage`.
- Claude Code 2.1.316 v1 uses only cumulative `modelUsage`, including every reported model. Overlapping `usage` is ignored. Direct, read, write, and output categories are all required for a complete total. Missing categories never fall back to the overlapping stream.
- Bindings persist ownership before native sends. This native launcher proves freshness by constructing an exec without resume arguments. A resume must bind an existing stream. Reusing a stream as fresh, resuming an unbound stream, changing its adapter, regressing a known model/category, or dropping a previously reported model refuses.
- Duplicates add zero across attempts and cannot authenticate a resumed attempt as complete. Exact replays are not appended again. The persisted-ledger normalizer also refuses duplicate stream/event identities, so stored rows cannot rebind an old event to a new attempt. Same-identity payload changes refuse using a bounded raw-payload digest. A missing category retains the earlier watermark. A later complete snapshot covers a gap. A new turn invalidates final coverage until another final snapshot arrives.
- Missing final coverage preserves a lower bound and reports an unknown final total. Required sends without corresponding final coverage cannot produce a complete stream report. Unreported helpers remain unknown.
- Uncached input is inclusive input minus cache reads. Claude direct input is separate; its uncached input includes cache writes. Missing reads makes uncached unknown. Reasoning is never added twice.
- Native raw accounting runs before display parsing. The native display parser does not create a second usage observer. Generic CLI protocol evaluation receives raw observations before its legacy display projection.

Claude remains an unpaid protocol fixture. No Claude native launch preparation or qualification is included. Resume math is covered with persisted/reloaded fixtures for both providers; the existing native launcher still constructs fresh Codex exec streams. Task size recording follows the existing Linux native host. Unavailable provider turn/call identity is null; host turn and call ordinals are not claimed as provider identities.

Result observations are buffered by the one host owner and flushed by the next existing raw/clock accounting publication, avoiding a new publication that would invalidate returned controls. They have the durability of that publication, rather than an independent per-result receipt. No terminal/recovery contract or tool reply is changed.

## Frozen corpus and prompt contracts

The corpus contains six synthetic talking-head cases, a timing-only audio fixture, and an authored transcript oracle. Its audio is not speech-recognition or live model-quality evidence. Every case checks exact operations, final document, unchanged objects, independent task/manual undo and redo histories, history restoration, project reopen, and production preview rendering.

1. Move marker 1 by one frame.
2. Delete the pause with an audio/ripple dependency outside the initial view. Missing edit authority refuses.
3. Trim linked media one frame before the next caption/word boundary.
4. Correct the homophone using neighbouring transcript/media evidence requirements.
5. Reject a plausible completed child with only one of two notes met and a failed proof. Its operations and wrong document are separate frozen fixtures.
6. Combined cut/caption work with revision refresh and preview requirements.

The expansion, rejection, and preview requirements are unpaid decision oracles. Scripted observations establish no live Director decision quality. Caption mutation uses the existing Motion role; Editor authority is unchanged.
