# JA-1 S6 G20: measurement report

G20 measures the proposed limits and targets in
`docs/JA1-STUDIO-ORCHESTRATION.md` §12. Ruling R6 narrows it to what the
existing instrumentation and a `/proc` sampler can reach through a scripted
host-level workflow. Every other target is listed as OPEN with its reason. A
MISS is reported, not fixed, in this commit.

## What ran

- **Workflow.** The `g20-measure` test
  (`crates/kinewright-agent/src/writer_host/review_s6_c5_measure.rs`) runs on
  the generated talking head (128×72, 30 fps, 6 s, stored transcript). It uses
  a scripted Reviewer over its own task MCP and runs no model. The sequence is:
  1. Queue.
  2. Encode, at the default delivery (`QueueDefault`, 1080p, −14 LUFS) and at
     source raster. Each run does both, as separate workflows.
  3. Check, with the production review driver. This includes the scripted
     Reviewer's stills read and judgment.
  4. Seal. The notification goes to a private `dbus-daemon`, never the
     session bus.
  5. Save to a temporary folder.
  6. 20 durable comments, then `ListVersions`.
  7. Detach, end the run, and wait for the exit.
  8. Reopen in a new host on the same bundle, then `ListVersions` again.

  Five runs per raster per lane, so 10 workflows per lane. Each workflow uses
  a fresh temporary folder under `target/`. The data, state, cache and config
  folders point inside the evidence folder.
- **Host shape.** The fixture runs the writer host in the test process, not as
  a separate child. "Host RSS" below therefore includes the host, the test
  driver, the scripted Reviewer's MCP client and the in-process encode engine.
  Separate processes in the tree: the MS2 media helper and supervisor, the
  fixture's `ffmpeg-testgen`, and the private `dbus-daemon`. There is no GUI,
  guardian process or provider child.
- **Sampler.** `scripts/measure-g20.py` reads `/proc` for the whole tree every
  50 ms. It records per-process peaks and the per-sample RSS sum. The
  simultaneous peak is the largest per-sample sum, never a sum of peaks.
  `nvidia-smi --query-compute-apps` is polled read-only every 0.5 s. No GPU,
  display or system setting changed.
- **Build.** The `g20` profile is release plus debug assertions. The debug
  assertions let the mutation build compile too.
- **Run conditions.** The runner was started with `setsid nohup`, at nice 19,
  with each lane under `timeout 600`. No build or test ran during the window.

  talking head is small.

  The host-only reopen above is the closest host measure.

## Mutation

`g20-comment-delay` adds 300 ms before every `SaveFeedback` durable write. It
builds only with debug assertions, and no shipping crate enables it. The
mutation ran on lavapipe with the same workflow:

| | Comment round trip p50 / p95 / max | `SaveFeedback` alone p95 |
| --- | --- | --- |
| Baseline (lavapipe) | 174 / 191 / 291 ms | 150 ms |
| Mutation (lavapipe) | 479 / **505** / 593 ms | 463 ms |

- **Result.** The p95 moved by 313 ms. That is the 300 ms delay plus noise, and
  the durable-comment target reads MISS under the mutation. The measurement
  sees a delayed durable write.
- **No cross-talk.** No other phase moved beyond noise.

## Files

- `g20-lavapipe.json`, `g20-nvidia.json` and `g20-mutation-lavapipe.json`:

  memory.

- Raw sample streams and logs stay in the evidence folder
  `target/ja1-s6-c5/<lane>/` and are not committed.
- **Reproduce:**
  1. Build the measurement binaries:

     ```bash
     cargo test -p kinewright-agent --lib --profile g20 --features g20-measure --no-run
     cargo build --profile g20 -p kinewright-media-helper --bin kinewright-media-helper \
       -p kinewright-media-supervisor --bin kinewright-media-supervisor
     ```

  2. Provision the fixture tools: `python3 scripts/build-ffmpeg.py --profile testgen`.
  3. Run `scripts/measure-g20.py --binary <test exe> --lane lavapipe|nvidia`.
