The existing seven HTTP MCP tools discover and invoke the task controls. The host session constructs `EffectPump` and drives it through the existing `pump_session`, outside the serialized owner. Task profile binding uses the actual authenticated task MCP endpoint. The production path has no `ContainedDriver` fallback. Its registration remains empty, runtime qualification refuses by default, and production launch requires a positive token ceiling. Protocol fixture ports are Linux `test-util` only and cannot qualify installed providers.

Explicit Freeze ends the host-owned work turn and publishes its exact checkpoint and H1 history together. Repeated Freeze and merge retain their original history/receipt. A frozen task can be restored for merge after its native attempt is archived without buying another child send. Result templates name the current accounting record. Completed result publication leaves an executing native attempt able to drain raw usage; Ready is published only after cleanup proof. Late results cannot join an already charged wake, and a native turn is offered only the deliveries in its charged payload.

The MCP witness performs acknowledged edits and Undo, turn exit, another attempt, automatic host recovery, frozen-result publication and merge, then Stop and reopen. Exact task/manual `HistorySnapshot` values, their non-empty redo tails, the merge receipt and saved Director setting survive.
