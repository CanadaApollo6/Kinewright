# S4b C2 guardian launch and first-send barrier

The original C2 evidence below covers `e8bda4d9`. The fix1 and fix2 follow-ups below record later changes; earlier final-gate counts belong to their stated baselines.

C2 uses two local commits. The first is `d8a63584`, the native filesystem, environment, and stdio foundation. The second connects the durable owner, immutable invocation, and restricted Codex session. Production connector registration stays empty. Installed-provider Studio starts have no direct-child fallback. Scripted host fixtures use a concrete `ScriptedDriver`.

The host stores the exact prompt and invocation manifest as owned evidence. One acknowledged orchestration cut consumes the send and changes its effect to a process-bound claim. Opening assignments, specialist starts, queued steering, and coalesced result wakes use this same path. The next native attempt cannot reuse a claimed effect or an already consumed attempt. A wake payload includes every coalesced result reference, with the parent identity checked.

The launcher rechecks the qualified profile and original effective launch context, reconstructs the actual recipe, and verifies the charged payload and manifest. The native owner rechecks the current project, run Producer, epoch, task liveness, and consumed send. It publishes the exact native recovery identity before COMMIT. Terminal and expired tasks refuse release. Steering remains queued in Reserved, Contained, Executing, and Waiting states without writing to an active provider or consuming another send.

The Linux provider inherits deny-by-default Landlock filesystem and IPC rules and a seccomp filter for metadata and descriptor escape operations. Runtime dependencies are read-only. Scratch and the credential store are private. Store entries must match the qualified credential, lock, or temporary-file names. Directory checks compare native identities through resolved ancestors. The executable is opened, checked by device and inode, and executed through the retained descriptor.

Provider input, output, diagnostics, and credentials use separate private Unix stream handles. Guardian control and lifetime remain separate. The final spawn clears the service environment and uses the validated environment. MCP secrets enter through the private credential handle, never Program, argv, receipts, or diagnostics. The restricted reader reuses the 64 KiB frame/ring limits and the 32-event queue with two terminal slots. Stop closes guardian lifetime independently of event capacity. Cleanup proof precedes machine-slot retirement. A failed cleanup releases the control lock before waiting for stderr.

The protocol child records execution, syncs its counter, and publishes an empty ready marker. The cuts before COMMIT and after COMMIT but before its EXECUTING acknowledgment both close and reopen the real project. They observe one durable charge, zero or one execution as appropriate, and no replacement authorization. Provider turn exit does not finish the task. C3 owns the remaining effect execution, raw usage, budgets, task-history continuation, and lifecycle publication.

All Cargo runs source FFmpeg, use `flock -o /tmp/kinewright-cargo-heavy.lock`, four build jobs, and worktree-local LOCALAPPDATA and TMPDIR. Normal gates use niceness 10 and four test threads. Mutation gates use niceness 19. Every Cargo/test invocation is bounded to 580 seconds or less; mutation invocations are bounded to 120 seconds. Final mutations run in foreground batches. Evidence remains untracked under `target/s4b-c2/`.

## C2 fix1 review follow-up

This follow-up starts at `e8bda4d939c44cc8177f4e9a5213a24255ba2782` and addresses Astra M1/M2, Muse's matching IPC Major, and the three Minors named in the amended fix1 brief. It adds one local commit and no push. All fresh evidence is under `target/s4b-c2-fix1/`.

Linux enters a fresh IPC namespace before readiness and refuses any unshare failure. Private tmpfs mounts hide both `/dev/shm` and `/dev/mqueue`. Seccomp also denies the SysV shared-memory, message-queue, semaphore, and POSIX `mq_*` families. The native fixture creates its own disposable host objects, probes them after the actual guardian's final exec, and verifies their contents remain intact. Its namespace-only case omits Landlock/seccomp to test the namespace and mounts independently. The sandbox child separately checks IPC syscall denial. The fixture removes only its own IDs and names, including on failure.

The serialized host registers an attempt-bound handle to the sole lifetime writer before publishing release authorization. It serializes the COMMIT write with Stop under the same host mutex. The grant-revocation boundary closes that registered writer before acknowledging Stop; it does not acquire the reader/cleanup mutex. The barrier witness accepts a current-revision Stop after durable authorization and before COMMIT, then observes zero executions and independent cleanup proof. The mirror witness keeps the returned session alive while Stop alone cancels its executing child. Model the Domain keeps the release decision in `NativeCommit`, and Boundary Discipline places cancellation in the shared grant-revocation path.

Opening, specialist-start, and result-wake effects are `ProcessBound` at creation, each covered by a creation test. The generic replay-safe outbox test now explicitly creates replay-safe work. Seccomp denies the six get/list-xattr calls and x86_64 syscall numbers 463–466 for the four `*xattrat` operations exposed by the installed kernel headers. The xattr witness includes an already-open outside file descriptor. `stat`, `statx`, and `readlink` metadata exposure remains an accepted Landlock limit; this work does not claim to hide file existence, size, timestamps, or link targets.

`StartupCleanup` owns every error after `prepare`, through pipe acceptance, credential transfer, COMMIT, and reader startup. It closes lifetime, attempts native cleanup synchronously, and retires only with a `CleanupProof`. Failure to prove cleanup retains the slot. The capacity witness fails launches at the pipe, credential, and reader stages on one machine claim, then starts a fourth attempt. Its fixture supplies compacted next-reservation metadata; it does not implement or qualify C3 history/recovery continuation.

## C2 fix2 owner-change revocation

This follow-up starts at `dd7433df66758b5306e45dcc5826453d4e67a6c1` and addresses Astra's executing-owner-change Major. Fresh logs remain untracked under `target/s4b-c2-fix2/`. The existing serialized command-completion boundary now checks every native registration against the current project and owner epoch, after success or failure and before returning the reply. A missing/unreadable owner also revokes. The check is unconditional, so stale registrations are closed even when the before/after owner snapshots are both unavailable. It closes the sole lifetime writer and removes only the authorization registration. It does not touch the machine claim. Startup and reader cleanup still require independent `CleanupProof` before retirement. The same host mutex orders this boundary with COMMIT, without taking the native reader/cleanup mutex.

| Transition audited | Coverage |
| --- | --- |
| Save As adopts a copied destination | Actual editor request after `execution-ready`; lifetime closes and cleanup retires the slot while the returned session remains alive. |
| Save As between registration/durable authorization and COMMIT | Condition-variable barrier; lifetime is already closed when Save As returns, attempt record remains until cleanup, and resumed startup produces zero execution. |
| FirstSave and RescueTo adoption | Both install owner/destination state inside the same completion boundary, including errors after installation. Source audit; no new native FirstSave/rescue replay. |
| Save/Retry copy promotion or writer reacquisition, Reconcile | Same boundary checks the resulting identity. Unchanged project/epoch remains valid; late copies do not themselves confer activation. Source audit. |
| Switch/OpenRecovery and recovery barriers | Same boundary covers working-edit/checkpoint selection and recovery confirmation. Same-project selection is not automatically a new project/epoch. Source audit. |
| Project-view replacement | A new host has a new owner; teardown of the old host closes its registrations through `Hooks::drop`. Runtime host-drop witness. |
| DetachForContinuation | Real request preserves the same owner, open lifetime, retained slot, and live native cgroup members. Refused Shutdown also preserves this live run. |
| Owner unavailable on a failed command | Fixture removes the owner, then executes a real failing Save through the shared executor. Revocation occurs even with both owner snapshots absent. |

The project-only and epoch-only witnesses seed stale registration tags, then run Status through the shared executor. These distinguish the two comparisons. They are scope checks, not alternate implementations of Save As. Host drop is exercised by dropping the real router/host while keeping the provider session alive. Allowed Shutdown still reaches router teardown and `Hooks::drop`; the live-run refusal is unchanged.
