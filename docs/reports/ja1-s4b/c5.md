## C5a design and boundaries

Model the Domain separates product specifications from fixture execution specifications. `certified_connectors` and Director choices never include fixtures, including feature-unified builds. Explicit fixture hosts use a separate saved-choice reader and factory; product Settings rejects the fixture and preserves an old saved selection as unavailable. Atomic setting persistence tests use an explicit fixture registry. Release-feature-graph and unified assertions test the product registry. `c1.md` corrects the old feature-unification claim.

Boundary Discipline puts TCP rights in the final Landlock ruleset. `ProviderSandbox::LinuxAllowlist.connect_tcp` carries the port set through the immutable invocation and guardian. The native recipe grants 443 and the actual validated loopback MCP port. Landlock handles TCP bind and connect, grants connect only, and grants no bind. Landlock port rules constrain ports, not destination IP addresses. The MCP binding itself accepts loopback URLs only. UDP/DNS is not claimed to be restricted by these TCP rights.

Codex runtime trees derive from the canonical, identity-checked executable. An npm package tree is read-only; otherwise only the executable's own directory is added. A grant containing HOME is refused, and the existing native-identity overlap check refuses project/store authority. Protocol fixtures do not inherit that product runtime grant. The recipe writes its direct-tool `models-direct.json` from bounded local model metadata, rejects absent model choices and changed files, and uses no paid discovery. This is runtime support, not installed-provider qualification.

`recover_on_open` finishes an empty machine claim before asking an unsaved session for a locator. A retained foreign or durable attempt still requires the existing recovery proofs. N1 has an unsaved/no-claim witness.

`read_provider_output` is the common bounded reader for the native launcher and CI protocol children. Raw H1 accounting precedes legacy display parsing. Legacy Cost events are suppressed before entering the native event queue. The CI cases cover malformed/oversized frames, duplicate/cache/missing usage, auth failure, queued steering and interruption after one acknowledged H1 send. Children are killed/reaped on parser refusal. Their retirement uses the fixture's never-dispatched fence and certifies no native provider or cleanup proof.

The throughput checkpoint keeps shared edits serial. The final sandbox and registry boundaries are established first. Protocol and runtime tests then exercise those boundaries. One implementation owner avoids concurrent writes to the guardian recipe and host state.

## C5b and the C1 contract amendment

C5a is local commit `58fad638c10b4d8fa036a87493eafbce9e6739f1`. C5b builds on it.

The lead amended the Codex credential contract on 2026-10-31. C1's atomic-replacement contract remains for Claude. Codex instead receives read access and in-place write access to one pinned credential file. This implements the installed CLI's version-tagged file-store behavior without requiring a different CLI or a second sign-in.

Each attempt has a private `CODEX_HOME` beneath private scratch. Kinewright writes its own config and an empty mount target. The guardian bind-mounts only the resolved `$CODEX_HOME/auth.json`, or `~/.codex/auth.json` when the variable is absent, onto that target. It never grants or mounts the original directory. Bind mounts exist only in the private payload mount namespace. Kinewright never copies, rewrites, caches, or repairs the credential contents.

`pin_credential_file` opens with NOFOLLOW and checks regular-file type, uid, mode 0600 or tighter, and dev/inode. The profile carries the pinned identity in its immutable manifest. The host rechecks before launch. The guardian checks at mount and at the final spawn boundary. After tree cleanup, the native worker checks the original file again before publishing successful completion. Failed startup cleanup also checks the file and publishes only failure. A mount point prevents rename, unlink, or replacement while permitting the CLI's in-place save.

The shared `job_guardian::credentials` parser retains only `auth_mode` and whether `OPENAI_API_KEY` has a non-null value. JSON null means no API key. Every other auth mode, a non-null API-key value, duplicate auth fields, malformed JSON, and any host `OPENAI_API_KEY` environment entry refuse. Unknown fields and all token values are skipped. Parser errors contain fixed messages. The final environment is cleared, and the CLI is forced to ChatGPT login with the file backend. The local authentication probe reads the same fields and returns Unauthenticated for an unreadable or torn file, feeding the existing Sign in readiness state independently of qualification. It never repairs the file.

Auth evidence now names launch and recheck observations. A Codex profile has no asserted post-exit observation before it runs. It does not claim a refresh merely because the file was read twice. Live refresh remains separately reported.

`InstalledCodexChecks` binds the resolved native executable to its SHA-256 and dev/inode, the selected model metadata, isolated recipe fingerprints, credential file identity, and Linux sandbox readiness. Runtime resolution supports the installed mise wrapper without executing Codex outside the guardian. Hashing streams from the opened binary with a 512 MiB bound and checks that size and modification time stay unchanged. The installed binary is 319,346,888 bytes.

The candidate is exactly Codex 0.166.0, SHA-256 `b8a11fedf24b2dfb59a70c9e52b030f9a508dcd49cd2dd0d41956f4c785156b8`. The person's configured default model is `gpt-6.1-sol`, with reasoning `high` and no service tier override. The local model catalog lists that model and supports high reasoning. The task ceiling is 16,384 tokens, with the plan's one-turn overshoot rule. The live witness also limits itself to one Editor, four total charged sends, and four minutes.

The [version-tagged exec options](https://github.com/openai/codex/blob/rust-v0.166.0/codex-rs/exec/src/cli.rs) support isolated user config, rules, and ephemeral execution. The recipe explicitly disables both generations of native multi-agent, plugins, hooks, shell tools, and the other ambient features.
