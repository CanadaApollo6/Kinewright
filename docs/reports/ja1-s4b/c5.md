## C5a design and boundaries

Model the Domain separates product specifications from fixture execution specifications. `certified_connectors` and Director choices never include fixtures, including feature-unified builds. Explicit fixture hosts use a separate saved-choice reader and factory; product Settings rejects the fixture and preserves an old saved selection as unavailable. Atomic setting persistence tests use an explicit fixture registry. Release-feature-graph and unified assertions test the product registry. `c1.md` corrects the old feature-unification claim.

Boundary Discipline puts TCP rights in the final Landlock ruleset. `ProviderSandbox::LinuxAllowlist.connect_tcp` carries the port set through the immutable invocation and guardian. The native recipe grants 443 and the actual validated loopback MCP port. Landlock handles TCP bind and connect, grants connect only, and grants no bind. Landlock port rules constrain ports, not destination IP addresses. The MCP binding itself accepts loopback URLs only. UDP/DNS is not claimed to be restricted by these TCP rights.

Codex runtime trees derive from the canonical, identity-checked executable. An npm package tree is read-only; otherwise only the executable's own directory is added. A grant containing HOME is refused, and the existing native-identity overlap check refuses project/store authority. Protocol fixtures do not inherit that product runtime grant. The recipe writes its direct-tool `models-direct.json` from bounded local model metadata, rejects absent model choices and changed files, and uses no paid discovery. This is runtime support, not installed-provider qualification.

`recover_on_open` finishes an empty machine claim before asking an unsaved session for a locator. A retained foreign or durable attempt still requires the existing recovery proofs. N1 has an unsaved/no-claim witness.

`read_provider_output` is the common bounded reader for the native launcher and CI protocol children. Raw H1 accounting precedes legacy display parsing. Legacy Cost events are suppressed before entering the native event queue. The CI cases cover malformed/oversized frames, duplicate/cache/missing usage, auth failure, queued steering and interruption after one acknowledged H1 send. Children are killed/reaped on parser refusal. Their retirement uses the fixture's never-dispatched fence and certifies no native provider or cleanup proof.

The throughput checkpoint keeps shared edits serial. The final sandbox and registry boundaries are established first. Protocol and runtime tests then exercise those boundaries. One implementation owner avoids concurrent writes to the guardian recipe and host state.

## C5 graph-depth class fix on f91a6110

The lead classified the depth failure as a C3 data-loss/recovery Major. The fix puts semantic history in the existing flat H1 run index, and replaces cumulative accounting in a separate current-snapshot slot. The ordinary B5 maintenance publisher commits that slot. Ticks and raw accounting updates do not allocate event segments, command receipts, or issuers. Native sends and user controls retain their durable receipts and semantic cuts.

`AccountingRecord` schema 3 keeps every original send, provider selection and usage sample in flat arrays. It no longer keeps snapshots of previous cumulative counters or an accounting-archive reference chain. Successor validation still prevents resetting allowances, counters, provider prefixes, sends or usage identities. Raw usage normalization and cache/reasoning counting are unchanged. Semantic cuts keep their original envelopes, receipts, snapshots and event segments. The flat index directly owns every segment; the segment's predecessor is a checked adjacency identity rather than another graph traversal edge. H1 checks adjacency before publication and again on reopen. Stop uses the same publisher and graph walker as other semantic updates.

A current cumulative snapshot can differ from the last semantic snapshot only in validated cumulative accounting and the corresponding expired-clock pause. Reopen validates those restrictions. An uncertain cumulative publication retains its exact identity and record in H3's pending-publication state. Reconciliation settles the shared H1 publisher and retries that original record; it cannot substitute another update. Internal run Producers reuse one subject-bound issuer for semantic publications. Explicit external issuer requests retain their existing behavior.

### Shared publication boundary and cut inventory

### Where invocation 7 stopped

### Root cause

Fix 1 mounted a mode-0000 tmpfs over the payload's `/proc` in `restrict_provider` at pid 1. Codex reads `/proc/self/exe` before it starts any turn:

- `codex-rs/arg0/src/lib.rs:203` sets `codex_self_exe = std::env::current_exe().ok()`.
- `codex-rs/exec/src/lib.rs:714` calls `ExecServerRuntimeOptions::from_optional_paths(codex_self_exe, …)?`.
- `codex-rs/exec-server/src/runtime_options.rs:35` returns `Codex executable path is not configured` when that path is `None`. `codex exec` exits 1.

`--version` returns before `run_main`, which is why the contained version probe passed. Invocation 6 ran before the mask and passed. Codex has no override variable for this path. The installed binary contains the error string (`codex-strings.txt`). Codex's other `codex_self_exe` use is the stdio MCP binding (`codex-mcp/src/binding.rs`); Kinewright uses HTTP MCP, so it is not reached.

The 250 ms observer identified providers only by an exe link beginning `/memfd:kinewright-provider`, and it skipped permission errors silently. A process that lives a few milliseconds is almost never sampled, so "no provider at any sample" is consistent with a provider that started and died at once.

The host also discarded the evidence. The guardian's init exited 1 silently after COMMIT, the host joined and dropped the provider's stderr capture, and a zero-frame EOF produced no run wait or refusal.

### Fix

- **Shared launch boundary** (`kinewright-job-sys` `restrict_provider`). The `/proc` mask is removed. The payload keeps its own pid-namespace procfs, so `/proc/self/exe` resolves to `/memfd:kinewright-provider (deleted)`. That path is absolute, and `from_optional_paths` accepts it.
- **No-swap guarantee kept.** The memfd, its digest check and `F_SEAL_WRITE | F_SEAL_GROW | F_SEAL_SHRINK | F_SEAL_SEAL` are unchanged, and exec is still `execveat(AT_EMPTY_PATH)` on that sealed image.
- **What replaces "not visible in /proc".** The image descriptor is CLOEXEC, so the provider's fd table never holds it. `/proc/self/exe` names only the sealed image. Opening it for write fails, and a read handle gives only the qualified bytes the provider already executes. Init drops its image descriptor right after spawn. Init's other descriptors are the COMMIT pipe (S4 R2C-M1 inventory), whose one byte init has already read, plus `/dev/null` stdio and Unix sockets, which `/proc` cannot reopen. This is the same `/proc` exposure invocation 6 ran under.
- **Lead decision.** This deviates from the A1 wording "not visible in /proc" and needs the lead's acceptance. Bind-mounting the memfd is impossible because its mount is internal. Copying the image to a file breaks the memory budget. `PR_SET_DUMPABLE=0` on init was not adopted. It would change who owns init's `/proc` entries, which the namespace check and the R2C-M1 witness read, so it needs its own review. It is a possible follow-up that would hide init's entries from the provider. Fix 4 adopts it.
- **Guardian.** After COMMIT, init now writes one line to the provider's diagnostics stream: `kinewright-guardian: provider exited with status N` or `kinewright-guardian: launch refused after commit: <error>`. The post-COMMIT body moved into `launch`, unchanged. **Superseded by fix 4**: the record now goes on the private credential socket.
- **Host.** The native worker counts provider stdout bytes. Suppose the provider produced no output, nobody stopped it and no other refusal is pending. The worker then builds a reason from the last three non-empty diagnostic lines: control characters stripped, the MCP bearer redacted, bounded to 512 bytes. It calls `InvocationOwner::launch_failed`, which `HostInvocationOwner` routes to the existing `record_runtime_refusal`. The run becomes Interrupted with `RunWait::Provider(reason)`, and Run view shows that reason as its stop reason. **Superseded by fix 4**: the reason no longer contains provider stderr.
- **No re-spend.** The interrupted effect stays outcome-unknown and is not re-sent, so a dead launch does not relaunch and spend again.

## C5 fix 4 — no provider stderr in durable evidence; non-dumpable init

Both rechecks closed fix 2 and confirmed fix 3's root cause. They found two security Majors in fix 3. Logs, the pair script and mutant hashes are under `target/s4b-c5-fix4/`.

### M1: provider stderr no longer reaches project evidence

Fix 3 copied the tail of provider stderr into the refusal reason, and H1 stored it as evidence. Only the exact MCP bearer was redacted. Because the capture kept the first 64 KiB, a bearer cut at that boundary survived as a fragment, and long stderr lost the guardian's line.

- **Guardian status on a private channel.** After COMMIT, init writes one framed record on its clone of the credential socket: `kinewright-guardian/1 exited N` or `kinewright-guardian/1 refused <io::ErrorKind>`. The clone is close-on-exec, and the pipe listeners are gone after accept, so the provider can neither write nor bury this record. The host reads at most 64 bytes after cleanup. A missing, oversized or malformed record, or a refusal kind that is not 1–32 ASCII letters, parses as `Unknown`, never as text. The stderr guardian line is removed.
- **Stderr is matched, never kept.** The worker drains provider stderr through a streaming matcher. It holds one 8 KiB buffer plus the longest pattern, and keeps only which allowlisted error appeared. The allowlist has one entry: `Codex executable path is not configured` maps to the fixed text `Codex could not resolve its own executable path`.
- **Reason text.** The stored reason is `the provider exited before its first event (status N)`, with `: <fixed text>` appended for a matched known error. A refusal reads `the provider launch was refused after commit (<Kind>)`, and a missing record reads `(status unknown)`. No provider-written byte reaches it, and no real credential is loaded to filter anything.
- **Other raw-capture paths.** The S4 native path was the only one storing provider stderr. The codex and network witnesses use stderr only for a sign-in prefix match and fixed categories, or discard it. The legacy direct drivers (`drivers.rs`, `acp.rs`) still put stderr into session error messages. That is pre-existing, outside the Studio native path, and unchanged. **Fixed by fix 5.**

### M2: namespace init is non-dumpable

- Init calls `prctl(PR_SET_DUMPABLE, 0)` through `kinewright_job_sys::make_payload_init_nondumpable` and checks it took effect. The call comes after procfs, credential, Landlock and seccomp setup and right before it spawns the provider. Its `/proc` entries then belong to root, which this user namespace does not map. The provider's exec resets its own dumpable state, so `/proc/self/exe` still resolves.
- Init still uses `/proc/self/fd` for its own grant descriptors before that point, and a process keeps access to its own entries in any case.
- The guardian starts the shim with a cleared environment, so namespace init inherits no environment block.

## C5 fix 6 — detection probes keep no provider bytes

Luna's fix 5 recheck promoted the detection-probe question to a security Major. `process_output` falls back to the whole stderr buffer when stdout is empty. ### Change

- A new portable module, `detection_probe.rs`, is the only place probe text becomes a kept value:
  - **Version.** `version_token` keeps the first token of this shape: an optional `v`, then two to four numbers of at most nine digits joined by dots. ## C5 fix 7 — provider stdin, first-progress deadline, unpaid dry launch

Invocations 7 and 8 both failed because a launch-path fix broke the real Codex startup, and no fixture could see it. Invocation 7 lost `/proc/self/exe` to fix 1's `/proc` mask. Invocation 8 hung on a stdin that fix 4 held open. This fix removes the defect and closes the class: the real CLI's startup through the real launch path is now exercised, unpaid and with egress denied, before any paid send. Logs are under `target/s4b-c5-fix7/`; the dry-launch records are `target/s4b-c5/dry-launch-*.json`.

### Stdin

- `ProviderPipes::into_reader` consumes the pipe set. It shuts down and drops the provider's stdin socket, and returns a `ProviderReader` that holds only stdout, stderr and the guardian's status channel.
- `launch_native` calls it right after the credential write and before COMMIT. The reader thread moves the `ProviderReader`, which has no stdin, so no later closure can hold stdin open again.
- `ProviderPipes::input` stays public for the guardian's `s4b-pipes` test, the one caller that writes to it.

### First-progress deadline

- `native_launcher::FIRST_PROGRESS` is 60 s. Codex `exec --json` writes `thread.started` within seconds of a healthy start: the dry launch measured 3.7–3.9 s. The longest startup wait in the retained Codex 0.166 source is one MCP server's 30 s startup timeout, so 60 s is twice that.
- Until the first stdout byte, the reader bounds each read by what is left of that deadline. At the deadline the stream reads as ended and is marked stalled. The ordinary end path then closes the lifetime, cleans up, completes and retires the attempt exactly once.
- A stalled, silent, unstopped launch reports the fixed reason `the provider started but sent nothing within 60 s`. It goes through the same `launch_failed` → `record_runtime_refusal` path as fix 3, with no relaunch and no second charge. Stop still wins: a stopped launch reports nothing.
- `NativeGuardianLauncher::first_progress` carries the value. Production takes it from `RuntimePorts::first_progress`, which defaults to `FIRST_PROGRESS`. Only the two fix 7 fixture modes shorten it, to 3 s.

### Unpaid dry launch

`kinewright_agent::writer_host::run_installed_codex_dry_launch` (on demand: `ja_s4_connector s4b_installed_codex_dry_launch`) launches the installed qualified Codex through the full product path. It uses the same disposable project, snapshot, note, batch and `ReviseCut` as the live witness (now the shared `start_director`), and so the same Director prompt, guardian, sealed image, sandbox, credential mount, arguments, environment, MCP config and stdin handling.

- **Egress denied.** While the `DenyProviderEgress` guard is held (`eval-harness` builds only; the shipping app has no such feature), every native sandbox allows TCP connect only to the loopback MCP port, not 443. It applies inside `sandbox()`, so the manifest charged at send and the one rebuilt at launch agree. Landlock mediates TCP connect by port; UDP is not mediated, so DNS still resolves.
- **Proof before launch.** `run_dry_network_witness` runs the existing network probe in that same policy. The control outside containment must pass, and inside containment TCP 443 to `chatgpt.com`, `api.openai.com` and `auth.openai.com` must be refused (`tcp_connect`), or nothing launches.
- **Pass criterion.** At least one of the three startup signals below, before the first-progress deadline plus 20 s. Each is recorded:
  - the first raw JSONL event, seen as a type token only;
  - an admitted request at the task MCP endpoint (`guard_mcp`), whose first request is the MCP `initialize`;
  - a network failure reported after turn start.

  A refusal, a runtime status or an interrupted run before any of them fails the dry launch.
- **Afterwards.** Stop is retried until it applies or the run ends. Cleanup must settle with every attempt retired and the manual history exact. The dry host is dropped before the guard is released. The credential's identity is checked read-only, and its mtime and ctime must be unchanged.

## C5 fix 8 — loopback-only network and read-only sign-in for the dry launch

Astra's fix 7 review (`.review/ja/review-ja1-s4b-c5-fix7-astra.md`) found two Majors, both in the dry launch:
- **M1.** The dry policy refused only TCP 443. Landlock mediates TCP connect by port, so TCP to other ports and all UDP could still leave the machine.
- **M2.** The dry launch mounted the live `auth.json` writable.

Lead ruling: a loopback-only network namespace and an init-held MCP relay for the dry policy only, with proof before launch inside the same namespace and policy and the credential mounted. Production launches are unchanged. Logs are under `target/s4b-c5-fix8/`; the policy records are `target/s4b-c5/unpaid-policy-*.json` and `target/s4b-c5/dry-launch-*.json`.

### The unpaid policy

`ProviderSandbox::LinuxAllowlist` gains `unpaid: Option<UnpaidPolicy { mcp_port }>`. `native_launcher::unpaid_policy` sets it only in `eval-harness` builds while `DenyProviderEgress` is engaged. It is `None` in every other build and launch, and it is omitted from the serialized manifest when `None`, so production manifests and digests are unchanged. Validation requires `connect_tcp == [mcp_port]` when it is set.

Under the unpaid policy:
1. **Network.** The guardian shim, still single-threaded, calls `isolate_payload_network()` after `enter_payload_boundary()` and before `fork_payload_init()`. It unshares `CLONE_NEWNET`, checks that `/proc/self/ns/net` changed, and brings `lo` up. Then it requires that the namespace has only `lo`, an empty IPv4 main table, and every IPv6 route on `lo`. Init and the provider live in that namespace, which has no route off the machine for any protocol.
2. **MCP relay.** Before launch, init connects a fifth private pipe, `relay`, beside the existing four. It binds `127.0.0.1:<mcp_port>` inside the namespace and starts a thread that accepts at most 4,096 connections. The thread passes each accepted socket to the host with `SCM_RIGHTS` and touches no bytes. The thread starts before `launch()` applies Landlock and seccomp to init's main thread, and it never runs provider code. On the host, `McpRelay` receives each descriptor and connects it to the real MCP listener on the host's `127.0.0.1:<mcp_port>`. It copies bytes both ways and holds at most 16 open connections. The bearer, `Host`/`Origin` checks and `guard_mcp` stay end to end. The relay belongs to the `ProviderReader` and is dropped when the run ends, which closes the channel and every connection.
3. **Sign-in.** Init bind-mounts `auth.json` and then remounts it `MS_BIND|MS_REMOUNT|MS_RDONLY`, keeping its locked flags. It checks the result with `statvfs` (`ST_RDONLY`) and pins the identity again. Init then checks the private per-attempt home before anything launches. `verify_unpaid_home` walks every entry, and `verify_unpaid_mounts` reads `/proc/self/mountinfo`. They refuse unless all of these hold:
   - The home is a private (`0700`-class) directory of this uid, on its own writable filesystem, and not itself a mount root.
   - The only mount at or beneath it is `auth.json`, mounted `ro`.
   - `auth.json` is a regular file carrying the sign-in's identity, on another mount, and read-only.
   - Every other entry is a directory, or a regular file with one link, on the home's own mount, and doesn't carry the sign-in's identity.
   - The home holds no symbolic links, no hard links and no other entry types.

   A refusal reads `unpaid_home_refused: …` and fails readiness, so nothing launches.

The home itself stays writable, as ruled. It is the discarded per-attempt `CODEX_HOME`, not the person's `~/.codex`.

## C5 fix 9 — socket-family allowlist for every provider launch

Astra's re-check of fix 8 (`.review/ja/recheck-ja1-s4b-c5-fix8-astra.md`) found one Major: AF_VSOCK escaped the unpaid boundary. On this kernel the payload's network namespace uses VSOCK mode `global`, which reaches listeners in other namespaces. The seccomp filter allowed `socket(AF_VSOCK)`, so a contained synthetic provider reached a host-namespace VSOCK listener while the fix 8 preflight passed. Logs are under `target/s4b-c5-fix9/`.

### Filter

`restrict_provider_syscalls` now checks the family of every `socket` and `socketpair` call against `PROVIDER_SOCKET_FAMILIES`, which holds AF_UNIX, AF_INET and AF_INET6. Every other family returns `EAFNOSUPPORT` (97). The lead ruled that this applies to **every** `LinuxAllowlist` launch, production included: it is strictly tighter, and it puts the paid path's filter under the dry launch. `ContainmentOnly` launches are unchanged; they install no seccomp filter.

Witnesses show that x32 `socket` and i386 `int 0x80` `socket` (number 359) both die with `SIGSYS`. Socket opcodes in `io_uring` stay closed, because `io_uring_setup` is already denied.

### Part 1: why `publish_result` was refused

### Part 2: a failed tool item is not a repair

`provider_failure` (`native_spending.rs`) follows Codex 0.166's schema (`target/s4b-c5c/upstream-codex-rs_exec_src_exec_events.rs`):
- Only `turn.failed` (`{"error":{"message"}}`) and a top-level `error` (`{"message"}`) are provider failures.
- The failure identity is `sha256(kind \0 field \0 value)`, taken from the first non-empty trimmed `code`, else `message`. Null, absent and empty values are never hashed.
- A failure with neither field gets the fixed token `UNCLASSIFIED_FAILURE` (64 zeros). Two unclassified failures never count as identical, and they still count toward the round and charge bounds.
- An `mcp_tool_call` item with `status: failed` (Codex's `error: null` shape included) falls through to the usage path. The model saw the refusal and can recover within its turn.

**Lead ruling (after review): Codex retry notices are not repairs.** In 0.166, Codex's own retry notices (`Reconnecting... N/5` and `Reconnecting... waiting for network`, `core/src/responses_retry.rs`) arrive as top-level `error` events while the turn keeps running. A top-level `error` whose message the reader's existing `transport_error` check recognizes is therefore neither a repair nor a repeat. It is bounded anyway: Codex stops after five retries and sends `turn.failed`, which counts, and the first-progress and run deadlines still apply. Every other top-level `error` still counts, and so does every `turn.failed`, network text included. (Fix 12 corrects the bound: it holds for the numbered notices only. The waiting-for-network notice has no count cap upstream, and its bound is the product run clock. See "C5 fix 12".)

| Ruling pair | Unit | Real reader and guardian (on demand) |
|---|---|---|
| Three `Reconnecting... N/5` notices, then `turn.completed` | No repair, no pause, the turn's usage is recorded | The turn completes, with no repair and no pause |
| `Reconnecting... 5/5`, then `turn.failed` | Exactly one repair round, classified by the `turn.failed` message | One round, no pause, one send |
| A non-retry top-level `error` | Still one repair round | n/a |

**Finding, not fixed here.** In the real-reader exhausted case, the provider exits after its one `turn.failed`. The task is not paused, so the reader refuses nothing. The run then ends only through the stall backstop: Interrupted with the generic `silent_stall` reason, not a reason specific to the failed turn, and no Director wake. Before this fix that state was a silent stall, and it applies to any single `turn.failed` followed by exit. The run is now visible, as part 3 requires. Waking the Director with a failure delivery instead is a separate decision.

### Part 3: no silent stall

At `c129d5f5`, a refused provider event left the run with no live provider, nothing scheduled and no reason shown:
1. The reader interrupted and killed the provider.
2. Nothing published why, and the run stayed `Pending`.

`machine::silently_stalled` is the invariant: outcome Pending, phase not Paused, Interrupted, Reviewing or Finished, no wait other than children, every attempt retired, and no effect next in its lane. It holds in exactly that state.

- **The reader names its refusal.** `read_provider_stream` returns a fixed reason (`STREAM_ACCOUNTING_REFUSED`, `STREAM_NATIVE_TOOL_REFUSED`, `STREAM_MALFORMED` or `STREAM_USAGE_UNRESOLVED`). It no longer sends the interrupt itself.

### Cause

Fix 2 made terminal authority belong to one publication, and refused it when the run's budget was inactive. `advance_run_budget` sets `budget.active` to false once the outcome is final and cleanup has settled. A finished, settled run therefore had no terminal authority at all. Its archive publication (`archive_retired_attempts`, then `publish_native`) satisfies `terminal_progress`, because it removes attempts and adds nothing. But the guard refused it with `run_limit`.

The run limit is not the trigger. The second witness below archives a run far below its limit and was red in the same way. The defect is the `!budget.active` half of the guard, for any finished and settled run.

**Production exposure is latent.** The only production caller of `archive_retired_attempts` is `reserve_native_effect` (`effect_execution.rs:36`), which runs for a pending run. No production path archives after settle today. A refused archive also loses no data: the retired attempts stay in the projection and reopen exactly. The fix is still held to the data-loss and spending tier, as directed, because a run must be able to finish cleanup and archive after Stop.

### Fix

`run_admission.rs` moves the terminal check into a helper, `terminal_authority(admitted, budget, before)`. It grants terminal authority when all of these are true:
- the run has an admitted budget (`index.budgets.contains_key(run)`). A run with no budget is still refused;
- the budget is active, **or** the run has finished (its outcome before the update is no longer `Pending`);
- fewer than `TERMINAL_CUTS` (32) terminal cuts have been used.

The fix 2 invariants still hold:
- **Terminal authority belongs to one publication.** The minted `TerminalAdmission` is still bound to the one `PublicationIdentity::Cut` of this update, and the call site is unchanged.
- **No spending past the limit.** `terminal_progress` still admits no new task, effect or attempt. `advance_run_budget` counts the cut as terminal escrow, so the 32-cut bound still holds. The witnesses check that the accounting is unchanged by the archive, and that a stopped run reserves no new send.

## C5 fix 14: a finished run spends terminal cuts only on archiving

Review of fix 13 (`741102aa`): Muse approved with 3 Minors (`.review/ja/review-ja1-s4b-c5-fix13-muse.md`). Astra requested changes with one Major (`.review/ja/review-ja1-s4b-c5-fix13-astra.md`, probe in `target/s4b-c5-review13-astra/`). CI on `741102aa` was green on Linux and Windows. This commit fixes the Major and the three Minors. Logs are under `target/s4b-c5-fix14/`. No paid run was made.

### Major: a finished run could burn its terminal reserve with no archival progress

Fix 13 gave a finished run with an inactive budget the whole of `terminal_progress`, not just the archive. Astra's probe stops and settles a run. It then publishes, through the run Producer and `publish_orchestration_transition`, an update that only changes `phase` from `Finished` to `Interrupted`, followed by an update that changes it back. The first is terminal progress and spends a terminal cut; the second is ordinary. After 31 rounds the real archive got `run_limit`, and reopen kept `terminal == 32` with the attempts unarchived. No production caller makes that cycle. It blocks the archive and deletes nothing. It is still a hole in the owner-publication boundary, because the reserve is meant to cover cleanup alone.

**Fix.** `run_admission()` now calls `cut_authority()` before any other admission, and it splits by the run's state before the update:
- **First cut, or a pending or still-cleaning run:** unchanged. A terminal cut while the budget is active follows fix 2's rule.
- **Terminal cut on a finished run whose budget is inactive:** allowed only for validated archival progress (`archival_progress`). That means:
  - outcome, phase, wait, cleanup, tasks, effects, deliveries, requests and results are unchanged;
  - at least one attempt is removed, every removed attempt is retired, and the remaining attempts are unchanged and in order;
  - the usage list changes only by replacing the attempt archive reference with one new reference, appended last. Every other reference, including the accounting reference, is unchanged;
  - the new reference is a sealed `AttemptArchive` record for this run. Its attempts are exactly the previous archive's attempts followed by the removed attempts. Project reads it from the store, so "sealed into the archive" is checked rather than assumed.
- **Any other change to a finished run whose budget is inactive:** refused with `run_limit`, whether or not it looks like terminal progress. Such a change is never counted as a cut.
  - One exception: a recorded refusal receipt (`decision != Applied`) whose projection is unchanged apart from sequence and control revision still takes the ordinary path. That keeps an Editor's control on a finished run recorded as a refusal, which Muse traced as a production path. No new fix 14 witness covers this exception; the existing suites pass with it.

`terminal_authority(admitted, budget, finished, archival)` is now a pure function. It refuses an unadmitted run or a used-up reserve first. It then allows an active budget, or a finished run whose archival check passes. The archival check runs only for an inactive budget.

After the archive, and again after reopen, it checks:
- that the archive is the prefix followed by every retired attempt, compared as full records (`C5_FIX14_ARCHIVE_EXACT`);
- that the full accounting is equal (`C5_FIX13_NO_SPENDING_AFTER_STOP`);
- that manual history is exact (`C5_FIX14_MANUAL_EXACT`).

**The restart variant.** A run that settled *before* a reopen is not retained by the new host: `run_producer` reports "run is not retained by this host", as Astra's first probe showed. So that run has no Producer to archive with, and no path archives it. The restart variant therefore restarts after Stop. The reopened host settles cleanup during its own recovery (`C5_FIX14_RESTART_STATE cleanup=Settled … retained=true`) and archives after that settle.

### Muse Minor 2: what makes up "no spending after finish"

`terminal_progress` alone is not a no-spend relation. The property is put together from these callers, and fix 14 changes only the first:
- **Run cuts:** `cut_authority` and `terminal_authority` (`run_admission.rs`). A finished run with an inactive budget makes only archival cuts and records only unchanged refusals.
- **Cumulative accounting**, where sends and token charges live: `accounting_recovery_admission` (`run_admission.rs:301`) returns no terminal token unless the budget is active. `consume_send` (`orchestration_accounting.rs:813`) refuses a paused task.
- **Native sends and charges:** `charge_native_invocation` (`native_invocation.rs:477`) and `queue_native_steering` (`:776`) go through `native_projection` (`:383`). That requires a live runtime grant (`RuntimeGrantBinding::live_in`, `orchestration.rs:106`: outcome `Pending`, phase not `Finished`, live task and attempt), outcome `Pending`, and a phase that is not Paused, Interrupted or Finished.
- **New attempts:** `reserve_native_effect` (`effect_execution.rs:24`) adds an attempt, so it is never terminal progress, and it refuses retired effect tasks.
- **Provider MCP:** `resolve_task_mcp` (`task_mcp.rs:429`) uses the same live binding, so a stopped endpoint cannot act.
- **Other host publishers after finish:** checkpoint, endpoint preparation and runtime-stop recording refuse or do nothing for a run that is not pending. Native completion and effect reconciliation return early once an attempt is retired.

Further hardening is deferred, as directed. That includes refusing an Applied ordinary write to a run that is finished but still cleaning, which fix 2's rule still allows.

## Certification dropped (2026-11-02, Riel)

On Riel's instruction, provider certification is no longer a requirement: it was a gate the project invented. The code no longer compiles in any release evidence (source, guardian and fixture hashes), no installed-binary SHA-256 pin (Codex's `CODEX_BINARY_SHA256` is gone), and no exact CLI version. `c5-release.json` stays in this folder as a historical report; no code reads it. What replaces the gate: each connector states a minimum CLI version (Codex `>= 0.166.0`), and the product probe reads the installed CLI's own `--version` at every admission. A newer CLI is allowed, because its stream stays under the same fail-closed allowlists: an unknown event, sign-in mode or ambient source still refuses the stream and retires the attempt. The executable is still measured while its size and mtime hold still, and sealed into a private image. `certified_connectors()` is now `available_connectors()`: every connector with a real adapter and launch recipe on this platform. Ordinary tests in `ja_s4_certification.rs` cover that the registry offers only such connectors, that the person must pick one explicitly, and that a saved choice, even an unavailable one, is kept as it is, shown as unavailable and never substituted.
