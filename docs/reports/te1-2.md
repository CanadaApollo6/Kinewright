## Reply and recovery contract

Previously, task controls travelled through `invoke_capability`. Most replies
contained only `receipt`; `task_status` supplied a separate `control`, and the
prompt required a status fetch before every control.

Task endpoints now expose direct role tools. A reply separates:

```json
{
  "version": 1,
  "outcome": {"receipt": "original receipt; operation data where applicable"},
  "receipt": "original host receipt, or null",
  "state": {"project": "...", "run": "...", "task": "...", "sequence": 42},
  "controls": {
    "id": {"issuer": "...", "sequence": 7},
    "attempt": "...",
    "expected_generation": 99,
    "owner_epoch": 1,
    "expected_head": "..."
  }
}
```

The example abbreviates the concrete state and receipt types. Current controls
come from live authorization after the outcome is known, including ordinary
errors. Terminal state is captured under the writer lock before attachment
retirement; terminal replies omit controls. Refresh failure cannot replace a
committed outcome. Evidence data cannot supply a top-level receipt or controls.
The response metadata does not alter the stored operation or replay identity.

Prompts, result wakes and MCP initialization use the same live context builder.
`task_status` remains available for recovery. An intervening publication can
stale a seed; its refusal returns refreshed controls rather than rebasing an
edit. Epoch, generation, head, attempt and existing exact revision checks remain.
Native recovery mode cannot issue live controls.

`HostCommand::ReconcileTaskReceipt` is a separate project-read route. It accepts
the original project/run/task/attempt/command ID and either the original typed
command or its canonical command digest. If both are supplied, they must agree.
The digest is SHA-256 of `kinewright.task-command.v1\0` followed by canonical
`serde_json` serialization of the typed command, omitting only a publication's
host-owned `result.usage_ref`. It needs no host grant reference, endpoint ID or
lost reply. All other publication fields remain part of the exact identity.

The route returns stored outcome and receipt, pending, or unknown. It checks
current or archived original attempt provenance and refuses changed payloads,
cross-task/run/project requests and mismatched digests. It issues no controls,
restores no actor, performs no merge and grants no terminal admission. A missing
merge step remains the responsibility of explicit trusted owner recovery.
Freeze results are retained with their original history so lookup can return
exact bytes across clock changes without reconstructing a live task. Merge
history retains the original Director attempt and logical command identity.

Legacy frozen histories without a retained result stay byte-identical when
checkpointed. The read route can return their stored receipt without inventing
an old computed result. A legacy merge without original attempt provenance
cannot be attributed to a current caller; trusted journal recovery remains
available. The two compatibility regressions failed before these guards.

Grant and issuer publication now occur together. Reusing a durable grant does
not make another maintenance publication. This closes the Save As dependency
gap exposed by initializing controls before the first tool call.
