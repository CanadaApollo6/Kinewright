# M19 captions

M19 derives captions from the timeline transcript in project-frame time. The
same pure cue builder feeds SubRip (`.srt`), WebVTT (`.vtt`), and burned-in
title generation. Linked A/V transcript copies are de-duplicated before cue
building, matching the transcript panel's editing view.

## Cue construction

Input words are already ordered and de-duplicated. A cue is accumulated from
their half-open project ranges. The builder applies these boundaries in order:

1. Break before a word when the gap after the preceding word exceeds half a
   second. Half a second is `round(project_fps / 2)` frames using the same
   integer nearest-rounding style as transcript cut margins.
2. Break after a word ending in `.`, `!`, or `?`. Closing straight or curly
   quotes, parentheses, brackets, and braces are ignored when checking the
   final punctuation.
3. Break before a word when joining it with single spaces would make the cue
   longer than 42 Unicode characters. An individual word longer than the
   limit remains one cue.

These rules prioritize natural sentence boundaries, avoid leaving a caption
visible across a meaningful silence, and keep unscripted fragments short
enough for a lower-third treatment. A cue starts at its first word and ends at
its last word plus a half-second reading hold. The hold is capped at the next
cue's start, so cues never overlap. Empty text and non-positive word ranges do
not produce zero-duration cues.

## Sidecar timestamps

Caption files use project frames and the exact project `Rational` frame rate.
Frame boundaries become milliseconds with integer `i128` arithmetic:

```text
milliseconds = floor(frames * 1000 * fps_denominator / fps_numerator)
```

SubRip uses `HH:MM:SS,mmm` and one-based numbered blocks. WebVTT begins with a
`WEBVTT` header and uses `HH:MM:SS.mmm`. Hours are padded to at least two
digits but are not constrained to a 24-hour clock. No floating-point time is
introduced.

The Export dialog contains a Captions row with `Save .srt` and `Save .vtt`
actions. Each action uses the native save-file dialog. Its default name comes
from the selected video export stem, then the first asset name, then
`captions`. The actions stay disabled until all timeline-media transcripts are
in a terminal ready state and at least one cue can be built.

## Burn-in titles

`Add captions` appears in the timeline transcript header action row. It sends
one batch containing:

- one new sync-locked video track, appended above every existing track; and
- one title clip per cue at the cue's exact project start and duration.

Caption titles use the sanctioned Small font-size token (`0`, 40 px at 1080
lines), the default `text-primary` color token (`0`), `LowerThird` position, a
background scrim, and zero-frame fades. Core allocates every title clip id.

Burned-in captions are ordinary title clips. Preview and video export use the
same title compositor, so caption position, font, color, and scrim export as
previewed instead of introducing a second subtitle-rendering path.

The whole track is generated by one `DoBatch`, so one undo restores the exact
pre-caption project snapshot. Captions are generated content, not a live view
of the transcript. Later transcript or timeline edits do not regenerate,
retime, or synchronize an existing caption track. To refresh captions, the
user deletes that track and runs `Add captions` again.
