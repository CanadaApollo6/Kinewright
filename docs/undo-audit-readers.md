# Readers of the old approval target-satisfaction shortcut

At base `1e2c4170`, the old audit can call approval A kept when A was discarded and another command B removed the same target. H2a part 2 follows command fate instead, per the user's ruling. No second approval-satisfaction answer is introduced. The differential recognizes only that precise cause and counts it. No reader below is migrated in this part. Recreation does not change a command's fate. The complete install rule, including the narrow Do uncertainty case for missing folded provenance, is stated in `history-rework.md`, “Kept beside the stacks” (the design source under `.review/arch`). Uncertain must be displayed separately and must not contribute to either kept or missing counts. The record deliberately does not identify earlier folded epochs: absent older-epoch commands without selected evidence report uncertain. The [review notes](undo-review-fixes.md#missing-epoch-provenance) preserve the executable information-loss probe and the ruling.

`EditApproval` is also re-exported by the host and serialized as part of its page. Searches found no further production consumer of its `applied` bit or missing/uncertain lists. Approval-reference vectors in run projections are different data: they bound and retain consent records, not the shortcut's answer. Test-only page constructors and assertions are excluded from this reader inventory.

The retained-work disclosure is also rendered at `crates/kinewright-app/src/ja1_attachment.rs:1937` (standalone recovery UI) and `crates/kinewright-app/src/ja1_host.rs:1323` (host recovery UI). Both display the composed text before offering retained-work actions; neither recomputes approval truth.

For missing folded provenance, the `studio_run_view` claims/counts and `retained_work` recovery guidance need an H2b document identity-effects check **only if** their chosen contract requires an exact final-document answer. The host audit composer and page serializer can forward `uncertain`; the three rendering sites can display its existing disclosure. No reader in this part treats uncertainty as applied, held, reversed or discarded.

Snapshot installation can re-apply an approved destructive command. Existing installation doors include host foreground snapshot adoption (`writer_host/mod.rs:1640`, called by Save `:2110`, Save As `:2121`, First Save `:2181`, Preview Rescue `:2234`, Preview Recovery `:2329`), GUI host activation (`editing_session.rs:676`), host shadow installation (`:782`), first-save rebound (`:816`) and bundle open (`:933`). Branch/checkpoint selection (`editing_session/switch.rs:65`), chosen rescue (`editing_session/rescue.rs:113`), frozen checkpoint installation/recovery (`editing_session/durable.rs:613`, `:827`), and the app's recovered host endpoint (`ja1_host_recovery.rs:121`) also restore selected histories. The lower `history_save.rs:117` adapter and `:127-142` frozen transition API implement several of these doors. H2b must decide at each exposed door whether re-application needs fresh approval; no such check is built here. Internal failed-publication rollback restores are not a new user-selected installation door.

Task/specialist resumption is the direct task-history installation door: `crates/kinewright-agent/src/durable_branch.rs:173` restores the persisted branch into its new actor. `crates/kinewright-project/src/bundle_recovery/restore.rs:173` materializes a chosen checkpoint for later selection, and `crates/kinewright-project/src/bundle.rs:702` restores an opened manual branch. In contrast, `crates/kinewright-agent/src/orchestration/tasks.rs:390` restores only a private consent-validation preview, and `crates/kinewright-app/src/chat_ui.rs:1516` installs a display-only host shadow; neither applies an edit in the real task actor. These distinctions matter for H2b's approval-door decision. Failed-publication rollback sites in `bundle_commit.rs` and the editing-session media/manual/durable adapters restore their pre-operation state and are separate from choosing a saved history.

An unhashed media resource is an external, unbound locator: owned media imports always carry hash and length, the owned-input matcher refuses a missing hash, and an owner record cannot bind that locator to an owned manifest or blob. The real import/collection test pins this on Linux; `unhashed_media_is_not_an_owned_blob_binding` runs without a store on every system.

Audit bindings use `get_exact(key, payload_digest)` or their unique consent reference. A key by itself can be ambiguous after installing folded sibling payloads; `get(key)` returns no entry in that case and must not be interpreted as an approval answer.
