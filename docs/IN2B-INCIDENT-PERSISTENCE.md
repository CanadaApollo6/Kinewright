### §0.4 Decisions this draft makes that no ruling covers

Each carries its reason. They are here rather than buried so a reviewer can refuse one without reading §§2–10.

- **d1 — the sidecar file is `<stem>.kinewright-incidents`** (brief Q0, unopposed; probe BP7 prototyped exactly this path shape and measured its four arms). Derivation mirrors `derive_lut_store` (`project.rs:134-141`). §2 rule 1.
- **d2 — the pairing digest is FNV-1a 64 over the saved project bytes, lowercase hex.** No new dependency (precedent: the fixture FNV pin IN2 §9.1 item 12); 16 hex chars in the envelope; collision resistance is not required — the digest catches file mix-ups, not adversaries. §2 rule 9.
- **d3 — the 7 new codes are new `LabelIncident` tail variants** (indices 17–23, POLICY rows 68–74), class `Explain`, predicate `Always`, severities per §5 rule 1. They are labels because every one of them carries untyped `Plain` evidence and no typed payload exists for any of them. The allowlist const stays `[IncidentCode; 54]`; the 7 are off it for IN2 §3.1 reason (2) — a session would spend a model to arrive at the sentence the card already shows — and E-B2 records the count change. The alternative, a new top-level `IncidentCode` variant, would shift every `table_index` after its insertion point; the tail append shifts none. §5.
- **d4 — the debounce bound is 2 s.** The app flushes the sidecar at most 2 s after the last log change, and always before close/exit returns and on every project save. The bound is a stated number so a hand-run can falsify it (§14 item 1); no `cargo test` asserts wall timing — the gate asserts the close path and an explicit `flush_incidents` seam (§2 rule 5, §12 clause 1). 2 s, not 200 ms (a flush per keystroke-close would churn the disk during incident storms) and not 30 s (the crash window, §13 limit 7, would eat whole sessions) — the middle the brief's "debounced" left open. §2.
- **d5 — the refused-op stash persists per record iff its serialised form is ≤ 4 096 B**, else the record omits it. That is the existing 4 096 B elision (IN2 §3.4 rule 23) applied at write: `Operation` already derives `Deserialize` (`operation.rs:22`), so the stash round-trips verbatim when it fits and degrades to "no refused op" when it does not, exactly as an over-ceiling opening message does today. Reusing the ceiling (rather than minting a sidecar-specific one) keeps one number for "an op too big to ship" everywhere it ships. §2 rule 3, §3 rule 13.
- **d6 — `RestoreReport { restored_open: usize, restored_resolved: usize, unknown_codes: Vec<(String, usize)>, rebased: usize, carried: Vec<String>, refused: BTreeMap<IncidentId, Operation> }`, and the write side returns `WriteReport { written_open, written_resolved, dropped_transient_open, pruned_resolved }`.** The transient-drop is enforced at write (N1/B3(i)'s "dropped at write"), so its count lives on the write report; restore is faithful (§2 rule 12, §3 rule 10). `carried` is the rule-8b opaque carry-through — raw record JSON texts (`Box<serde_json::value::RawValue>` at the split, re-emitted verbatim, never pruned; `String`, not `Value`, so core gains no `serde_json` dependency and the round trip is byte-equal, not value-equal); `refused` is the rule-13 stash keyed by id. Every field is asserted by §12; a report that names only counts cannot pass over an empty sidecar. §§2–3.
- **d13 — the two `&'static str` evidence leaves become `String` in production** (`MediaError.code`, `incident.rs:996`; `SourceEdit.reason`, `:1010`), wire-identical. The alternative N1/S2 permits — a record-local evidence mirror — would need a lossy or leaking back-conversion to `&'static str` at restore; production-owned strings make `IncidentEvidence` deserialise whole with zero special cases, and every construction site is compile-forced (`MediaError.code`: 2 production sites, both writing `code.code()` already — `incident.rs:1640`, `media_workflow.rs:2033`; `SourceEdit.reason`: 1 production site, `media_workflow.rs:201-203`). §2 rule 3, §3 rule 2.
- **d14 — payload stops are prefixed at build** (`investigator.rs:1580` → `"harness: {message}"`, `:1603` → `"observer: {reason}"`) so core's §2 rule 14 categoriser can tell a Harness payload from an Observer payload after the typed stop is gone. The live card gains the stop kind; no gate test asserts a payload stop verbatim (probe-2 re-runs the full suite to confirm). §2 rule 14.
- **d15 — `SUBJECT_NAME_CEILING_BYTES: usize = 64`**, bounding the **serialised** name via `truncate_to_serialized_bytes` (`incident.rs:1245`). The wire arm is then at most `,"subject_name":"<64>"` = 82 B, exactly probe BP4's measured name delta. §9 rule 5, §10 rule 5.
- **d16 — new `MediaError::Scope(ScopeError)` variant** (the IN1b §3.9 rule 36 precedent: matte errors ride typed the same way). `scope_measurement_from_proof`'s three flattened errors unify as `MediaError` — `MatteCoverageError` via the existing `From`, `ScopeError` via the new variant — and `recovery_code` answers `None` for it, routing to `media_backend_unclassified` per IN1b §5.1 rule 11 step 1. The alternative (a new error enum per call site) would leave the note without `from_media_error`'s total mapping. §6 rule 2.
- **d17 — one app-side `WorkerError { Untyped(String), Media(MediaError) }`** carried by all four panel worker channels and both export-verification enums. Proof strings (flattened at the excluded seventh seam), worker panics and collapses have no typed error behind them and must stay distinguishable from typed `MediaError`s — wrapping them as `Backend` would misclassify (e.g. a `SourceColorForAsset` proof failure reported as unclassified). `Untyped` notes `panel_worker_error` (no session); `Media` notes `from_media_error` (per allowlist). §5 rule 4, §6 rules 2–5, §7.

The seam's retype to `ColorQcError` leaves this synthesised `String` with no variant; the refused/missing proof is the nearest typed neighbor, and the original sentence survives verbatim in the note's `observed`, so nothing is lost. §6 rule 3.

Builders set `None`/`false`; the router sets `Some`; `observe` truncates and stores. The alternative (an `observe` parameter) would churn 61 test call sites for a value only production supplies. §9 rule 5.

- **d7 — newer, mismatched AND corrupt sidecars are renamed to a first-free `.bak`** (N2/B-6, N2/S-16: rev1 left corrupt sidecars in place; temp+rename means a crashed Part-B write tears the temp, never the sidecar — so a corrupt sidecar is a hand edit or disk damage worth preserving, not a torn write the next save should silently overwrite). A newer sidecar belongs to a newer writer (overwriting it would destroy history the current build cannot read); a mismatched sidecar belongs to a different project file (same reason). All three refuse the load and note exactly one incident. A newer build never reads a `.bak` on its own — the person renames it back by hand (N-10). §2 rule 8.
- **d8 — Save As leaves the old sidecar in place** and writes a fresh one at the new stem carrying the live log with the digest recomputed over the new bytes. The old sidecar belongs to the old path; deleting it would destroy the old project's history. §2 rule 7.

Pure means: no clock, no document, no log — the observation carries the worker's stored strings verbatim. §7 rules 2–3.
- **d10 — gate tests are named `in2b_…`** and live with the surface they assert (core unit tests in `incident.rs`, app tests over the real router headlessly, agent tests in `server.rs`/`mcp_server.rs`). §12.

Coupling them would force a sidecar bump every time the document format moves and vice versa. §§2, 4.
- **d12 — cross-run `observed` duplicates for non-panel codes are accepted** (OQ2's "accepted otherwise"): a reopened open incident re-observed under a new temp path dedups against nothing and opens a second incident. Normalising paths at note time would falsify the evidence the card shows; the duplicate is honest staleness in the same class as §9's renamed-asset names. §3 rule 7.

**Why d3, d13 and d17 are shaped the way they are** (the three decisions a reviewer is most likely to refuse, with the alternatives priced):

- **d3 (tail variants, not a new top-level variant).** A new `IncidentCode` variant inserted anywhere but the end shifts every `table_index` after it — POLICY rows, the allowlist slice, `from_code`'s scan order, and every test that pins an index. The tail append shifts nothing: rows 0–66 are byte-identical, the allowlist slice is untouched, and the only tests that move are the ones that count rows (E-B2/E-B9 name them). The price is conceptual: the seven are `Label`s, so `Label` now means "untyped evidence" rather than "source label" — the `LabelIncident` doc gains one sentence saying so.
- **d13 (production `String` leaves, not a record mirror).** A record-local evidence mirror needs a back-conversion to `&'static str` at restore — a match against fixed sets (lossy on drift), a `Box::leak` per restored incident (unbounded over runs), or a global interner (a new wheel). Production-owned strings need none of the three: the wire bytes are identical (`str` and `String` serialise the same), every construction site is compile-forced (3 production sites), and restore is total by construction. The price is 3 changed lines in production evidence — the cheapest totality on offer.
- **d17 (one `WorkerError`, not per-panel enums or `Backend` wraps).** Per-panel enums (4+ two-variant types) would each need their own mapping arm in every consumer; `Backend` wraps would misclassify flattened strings (a `SourceColorForAsset` proof failure reported as unclassified — a lie about what Kinewright knows, and a lost auto-apply). ## §2 The sidecar

1. **The file is `<stem>.kinewright-incidents`, JSON, beside the project** (d1). Derivation mirrors `derive_lut_store` (`project.rs:134-141`), which maps a project path to `<stem>.kinewright-assets` (`lut_store.rs:285-315`): `None` project path yields `None` and no IO is attempted (rule 10). Serialisation is `serde_json::to_string_pretty`, the same shape `write_project_document` uses (`project.rs:186-220`); probe BP7 measured 3 incidents at **2 370 B** in this shape. Pretty, not compact: the sidecar is a debugging surface (Riel diffs it by hand in §14 item 5), and the 629 kB bound already assumes worst-case records — readability wins over bytes the bound allows. **Rejected: a `Document` field** (incidents would become undoable and branchable — Ctrl+Z un-resolving an incident, every agent branch forking the log — and it re-pays the 52-site toll IN2 §2.4 measured). **Rejected: a per-user store**: incidents describe *this project* (evidence carries asset ids, revisions and observed values meaningless elsewhere); a per-user store breaks "open the project on another machine", needs its own project-identity key, and travels nowhere when the project file is copied (N1/S5's rewording — the rejection stands on identity and ownership, not on the two-process defect, which the sidecar shares per rule 10).
2. **The envelope is `{ format_version: u32, project_digest: String, previous_digest: String, records: Vec<IncidentRecord> }`.** `format_version` is always written, starts at 1, and is independent of the project's (§0.4 d11). `project_digest`/`previous_digest` are the FNV-1a 64 of the saved project bytes as 16 lowercase hex chars (§0.4 d2, rule 9: the sidecar is written *before* the project bytes, so it carries the incoming digest and the outgoing one). Loading returns a four-arm enum `Absent` / `Current` / `Newer(u32)` / `Corrupt(String)`, exactly the shape probe BP7 prototyped and measured. A versionless sidecar is `Corrupt("missing format_version")`, **not** defaulted: the sidecar has no legacy, so unlike the `Document` it defaults nothing — a versionless sidecar is a foreign or hand-written file (N1.1/OQ4). The asymmetry is stated, not buried: the `Document` must default for legacy files; the sidecar must not. **Future-writer rule** (N2/B-6): any change to the `IncidentRecord` shape or to the `IncidentState`/`IncidentOutcome` variant set **bumps the sidecar `format_version`**; an older reader meeting a newer sidecar version takes the `Newer` arm (rule 8) and never rewrites what it cannot parse (rule 8's carry-through). The envelope itself is parsed with `records: Vec<Box<serde_json::value::RawValue>>` — per-record deserialise (rule 8, §3 rule 1).
3. **The record is `IncidentRecord`, a core type distinct from the wire shape** (N1/S2), `Serialize` + `Deserialize`, with exactly these fields and no others:

   | field | type | notes |
   | --- | --- | --- |
   | `id` | `IncidentId` | resumes `next_id` above the loaded maximum (§3 rule 1) |
   | `code` | `String` | the IN1 §2.2 rule 5 wire value; `from_code` at restore, unknown → aggregate (§3 rules 3, 6) |
   | `subject` | `IncidentSubject` | gains `Deserialize`; `AudioChain` gains the 1-line derive (`media.rs:1178-1182`, BP1) |
   | `observed` / `allowed` | `String` / `Option<String>` | evidence strings, verbatim |
   | `evidence` | `IncidentEvidence` | gains `Deserialize` whole (§0.4 d13: the two `&'static str` leaves become `String` in production — wire-identical, `str` and `String` serialise the same — so no parallel mirror drifts; `IncidentFamily` gains the 1-line derive, `operation.rs:4925`) |
   | `revision` | `TimelineRevision` | rebased at restore (§3 rule 9) |
   | `opened_wall_millis` | `Option<i64>` | wall = origin + `opened_at`, derived at write (N1/B4); `None` when the log has no wall origin |
   | `opened_offset_nanos` | `u64` | `opened_at.as_nanos()`: exact session order incl. same-millis ties (N1/S2) |
   | `count` | `u32` | verbatim |
   | `state` | `IncidentState` | gains `Deserialize`, `#[serde(flatten)]` as on the wire (`incident.rs:1359-1360`; adjacently tagged `tag = "state"`, `:1095`); the writer emits only `Open` / `Resolved` (§3 rule 4) |
   | `telemetry` | `IncidentTelemetry` | gains `Deserialize` with `IncidentResolver` (all leaves already owned, `Duration`s serde-native); `stop` categorised at write (rule 14); **`resolved_after` is `#[serde(skip)]`** (N2/N-9: it is log-origin-relative (`incident.rs:2997`), meaningless across runs — restored telemetry reads `None` until the incident is resolved again) |
   | `proposal` | `Option<IncidentProposal>` | gains `Deserialize`; `operations` is `#[serde(skip)]` and deserialises to `[]` (BP1 measured); `stale` forced `true` at load (IN2 §4.2 rule 10) |
   | `subject_name` | `Option<String>` | §9 |
   | `refused_op` | `Option<Operation>` | N1/B3(iii), §0.4 d5: persisted iff its serialised form is ≤ 4 096 B, else omitted |

   **Why each field is in or out.** `id` (identity across restores — dedup keys and card references survive); `code` as `String` (forward-compatible with codes this build predates — rule 6's aggregate needs the raw string); `subject` (dedup axis + card anchor); `observed`/`allowed` (frozen evidence — the card shows what was seen, not what is); `evidence` (the typed payload sessions and recoveries read); `revision` (rebase input, rule 9); wall + offset (recency + order, B4/S2); `count` (episode weight — "seen 12" survives); `state` (the todo list itself); `telemetry` (spend accounting survives — budgets are per-run but history is forever); `proposal` minus operations (the person's pending decision, safely stale); `subject_name` (the name when seen); `refused_op` (the session's opening context, B3(iii)). Out: everything derivable (`class`, `severity`, `field`, `recoveries` — the single producer IN1 §9 clause 6 pins), everything session-local (`suppressed`, queue, threads), everything rebuildable (`loaded_*`, `next_id`). A loaded incident therefore always agrees with the *current* policy table (§3 rule 2). What is *not* in the record cannot drift from it. All record `Option` fields (`allowed`, `opened_wall_millis`, `proposal`, `subject_name`, `refused_op`) carry `skip_serializing_if = "Option::is_none"` — the sidecar omits what is absent, as the wire does.
4. **The sidecar is written whenever the log changes** (N1/B1): on every log change debounced at most 2 s (§0.4 d4) off the frame thread, on project close, on app exit, and on every project save — the save-time write is what keeps the digest pair equal to the bytes on disk (rule 9). Writing is independent of document dirty state, and log activity never marks the project dirty: `is_dirty` stays document(+mutes)-only (`project.rs:469`, critic N1) and no sidecar path touches it. The close/exit hook is **`ProjectSession::stop_threads`, after `shutdown_for_close`** (N2/B-5 — rev1's dirty-prompt sites `app.rs:977`, `:1024`, `:1038-1047` are NOT the hook: they miss headless closes and double-flush; `stop_threads` covers `close_project` `app.rs:994`, `request_exit` `:1031`, and headless tests): the sidecar flushes whether or not the project is dirty, which is the whole of B1 — a proposal recorded after the last document save survives close/reopen (§12 clause 1). **Change signal** (N2/S-6): core gains `IncidentLog::generation() -> u64`, bumped by **every** `&mut` writer on the log (`observe`, `resolve`, `note_auto_applied`, proposal/telemetry writers, `restore` — the MCP threads mutate through the same handle, so they count too; stage A); the flusher decides with the pure `should_flush(last_change: u64, last_written_gen: u64, now: Instant) -> bool` (`last_change > last_written_gen`, edge-triggered by the 2 s timer — no wall-timing assert in any test). A flush that finds `generation() == last_written_gen` skips the IO (N-5: the skipped job reports `Skipped`, asserted by item 17's derivation-`None` half for unsaved projects).
5. **One synchronous seam, `flush_incidents()`, builds every write; ONE writer thread per app lands the bytes** (N2/B-5 — rev1's "debounced and synchronous writes" are unsequenced: an old snapshot overwrites a newer one, an old digest lands after a save's new digest → mismatch → `.bak`, and a shared `.tmp` clobbers). Records are built on the frame thread under a **read lock** (`IncidentLogHandle.read()`); the serialised bytes go to a single per-app writer thread. Jobs are keyed by sidecar path and **sequence-numbered**; a newer job for a path drops an older still-queued one (stale jobs never land); every job writes a **per-job unique temp name** (`<stem>.kinewright-incidents.<seq>.tmp` — never a shared `.tmp`). `flush_incidents()` returns `io::Result<WriteReport>` — `Ok` after a successful temp+rename (report populated), `Err` after a failed one (the caller notes `sidecar_write_failed` per rule 6 and carries on). **Close/exit/save send and join**: the `stop_threads` hook (rule 4), `request_exit`, and the save path block until the writer thread acknowledges the final job — returning before the bytes land would reintroduce B1's exact bug. §12 asserts the sequencing, never wall timing: the gate box (clause 1) starts a save while a background write is in flight and asserts the sidecar on disk carries the save's digest pair. **Load** (N2/B-1 — rev1's hook misses startup reopen: `KinewrightApp::new` loads at `app.rs:359` and calls `ProjectSession::create` at `app.rs:399`, bypassing `create_project_session` `:637`): the load lives in **`ProjectSession::create` behind a mode** `SidecarMode { Load { digest-gated }, RecoveryNoDigest, None }`, and **all four sites pass one** — startup reopen (`app.rs:399`: `Load`), new project (`app.rs:837` via `:648`: `None`), `open_project` (`app.rs:876` via `:648`: `Load`), recovery restore (`app.rs:2222` via `:648`: `RecoveryNoDigest`). `ProjectSession::create` runs headless in tests (`project.rs:1295`, `app.rs:4609`), so clause 1 / item 14 reach restore through it with no GUI.
6. **Writes are atomic: per-job unique temp file + rename** (N1/S5, N2/B-5 rule-5 temp naming), unlike the project file's own plain `fs::write` (`project.rs:192`), which this contract does not change. **A sidecar write failure never fails a project save**: the save returns success and the log notes exactly one `sidecar_write_failed` incident (§5 rule 1). No retry — the next trigger rewrites the whole file, so a retry would only repeat the failure faster.
7. **Save As writes a fresh sidecar at the new stem carrying the live log** (N1/S5), with the digest recomputed over the new bytes; the old sidecar is left in place (§0.4 d8). The LUT-store precedent copies stores on Save As (`project.rs:207-214`); the sidecar is cheaper than a copy — it is rewritten from the live log, so it cannot carry stale records. **Save As additionally drops any open `project_newer_format` incident from the live log** (N2/B-4): the note was about the old path's bytes (a newer writer's file); the new path holds this build's bytes, so carrying the note would badge a clean copy with a false card (rev1's §14-item-4 contradiction). The drop is a live-log removal, not a resolution — no `Resolved` is recorded, no suppression is written.
8. **Failure arms on load** (probe BP7's measured table, plus N1.1/OQ4, §0.4 d7, N2/B-6, N2/S-16):

   | sidecar | load | project | incident | file after |
   | --- | --- | --- | --- | --- |
   | missing | `Absent`: empty log, silent | opens | none (history is recoverable state) | — |
   | corrupt (truncated, torn, invalid JSON) | `Corrupt`: refused | opens | exactly one `sidecar_refused` | renamed to first-free `.bak` (rule 8a); the next save writes fresh |
   | valid JSON, no `format_version` | `Corrupt("missing format_version")` | opens | exactly one `sidecar_refused` | renamed to first-free `.bak` |
   | `format_version` newer than this build | `Newer(v)`: refused | opens | exactly one `sidecar_refused` | renamed to first-free `.bak`, never deleted |
   | digest mismatch | refused (rule 9) | opens | exactly one `sidecar_refused` | renamed to first-free `.bak`, never deleted |
   | valid envelope, ≥ 1 unparseable record | `Current` + carry-through (rule 8b) | opens | none for the carried records (plus the rule-6 aggregate iff a *parsed* record carries an unknown code) | — |
   | `format_version` older (0) | `Current` | opens | none — the gate is newer-side only (BP7) | — |

   Every arm opens the project: incidents are recoverable state, the timeline is not. No arm deletes a sidecar it cannot read.

   **Arm rationales, one line each.** Missing/silent: a fresh checkout, a copied project, a deleted sidecar — all legitimate, none an error, and an incident for "no history" would badge every new project (the (c) lesson, §7 rule 8). Corrupt/`.bak`: temp+rename means a crashed Part-B write tears the temp, never the sidecar — so a corrupt sidecar is a hand edit or disk damage worth preserving for inspection, and the next save *would* overwrite it (rev1's left-in-place lost the evidence; N2/B-6). Versionless/`.bak`: a hand-written or foreign JSON file — same disposition as corrupt, distinct message. Newer/`.bak`: belongs to a newer writer; overwriting it would destroy history this build cannot read, and the next save *would* overwrite it — hence the rename, which preserves it for the newer build (a newer build never reads the `.bak` on its own — N-10, §0.4 d7). Mismatched/`.bak`: belongs to a different project file; same preservation logic. Older(0)/silent: forward-compatible by construction — version 0 has no fields version 1 lacks (both versions' schemas are this contract's), so the gate is newer-side only.

   **Rule 8a — first-free `.bak`** (N2/S-16): the rename target is `<stem>.kinewright-incidents.bak`, or `.bak.1`, `.bak.2`, … — the first name that does not already exist. A second refusal never overwrites the first (rev1's `fs::rename` clobbered it). Item 15 refuses twice and asserts both files' bytes.

   **Rule 8b — per-record parse with opaque carry-through** (N2/B-6): the envelope parses `records` as `Vec<Box<serde_json::value::RawValue>>` and deserialises each element separately into `IncidentRecord` (rev1's `Vec<IncidentRecord>` failed the whole file on any new variant — and the next flush then destroyed the unreadable history, which is also what made rev1's rule-5 body #5 "open in a newer Kinewright" a lie within 2 s). Records that parse restore normally; records that do not (unknown variant, newer shape) are carried **verbatim** — raw JSON texts in `RestoreReport.carried` (d6), re-emitted byte-equal on the next write, never counted in the prune bound (rule 11 counts parsed resolved records only). One bad record neither refuses the file nor loses its bytes: §12 clause 12 asserts the unknown-record byte-equal round trip (the carried bytes appear verbatim in the rewritten sidecar; consecutive writes are byte-identical) and the one-bad-record-still-loads arm.
9. **Pairing by digest of the parsed bytes, sidecar before project** (N1/S5, §0.4 d2, N2/S-1 — rev1's `load_document`-returns-`(Document, u32)` needs a second read (TOCTOU), its debounced-flush digest is unspecified, and project-`fs::write`-then-sidecar crashes between the two into a permanent `.bak`). `load_document` returns the document with the digest of the **parsed bytes** (the exact bytes the parse consumed — no second read); `write_project_document` returns its digest in a `ProjectSaveReport`; `ProjectSession` keeps `saved_digest: String` (the digest of the project bytes on disk as this session last saw them). **The sidecar is written *before* the project bytes**, carrying `{project_digest, previous_digest}` = `{saved_digest, saved_digest-before-this-save}` — i.e. the digest the project file is about to have and the digest it had. At load the app recomputes over the project bytes and accepts the sidecar when **either** digest matches (a crash between the sidecar write and the project write leaves the *previous* digest matching — no false `.bak`). Mismatch of both ⇒ rule 8's mismatch arm. Debounced background flushes always write the live `saved_digest` in both fields (no project write is in flight — there is no "outgoing" digest yet). This is brief R1's mitigation restated as a mechanism: a person who copies the `.kinewright` file without its sidecar gets a silent empty log (missing arm); a person who pairs a project file with another project's sidecar gets one incident and a `.bak`, not silent corruption. The digest catches file mix-ups, not adversaries, and the contract says so (§0.4 d2).
10. **Unsaved projects do no sidecar IO** (N1/B1): derivation returns `None` (the `derive_lut_store` shape, `project.rs:134-141`); nothing to load, nothing written; the first save writes it. **Two processes on one project are last-writer-wins, stated** (N1/S5, N1.1/OQ5): no file locking (the same consistency as the project file itself); temp+rename removes the torn reads probe BP7 measured at 14/2 000 loads (0.7 %) under plain `fs::write`, and §12 clause 11 asserts a mid-write load never tears. One writer's tail can still be lost; the contract says that sentence. Concretely: process A (log: incidents 1–10) and process B (log: incidents 1–12, where 11–12 are B-only) both flush — whoever renames last wins the whole file, and the loser's B-only incidents survive only in its live log until its next flush, which then overwrites the winner's. No merge, no conflict incident (a conflict incident would itself be overwritten) — the same semantics as two processes saving one `.kinewright` file, which also last-writer-wins today. **One session per canonical path within a process** (N2/S-13 — `open_project` is unguarded today, and recovery `app.rs:2222` can land on an open path): opening a path whose canonical form already has a session **focuses the existing session** instead of creating a second (no second log, no second sidecar writer, no incident — focusing is silent); a recovery restore whose target path is already open runs `RecoveryNoDigest` (rule 5) and writes **no sidecar** until Save As gives the recovered document its own path.
11. **The bound is real** (N1/S4, N2/B-2): at write, resolved incidents beyond the most recent **256** are pruned oldest-first **ordered by `IncidentId`** (rev1 ordered by `opened_wall_millis` — but cross-run offsets are incomparable once the origin changes, so wall order mis-prunes; `IncidentId` is monotonic across runs because `next_id` resumes above the loaded maximum at restore, §3 rule 1). Open incidents are **never** pruned. The only unbounded open producers — transient panel-state notes re-observed every run — are removed by rule 12, so "open uncapped" cannot grow without bound across runs. The write returns `WriteReport { written_open, written_resolved, dropped_transient_open, pruned_resolved }`; §12 clause 2 asserts `pruned_resolved` over a 300-resolved log.
12. **The persisted-Open set excludes transient observations, by provenance not by code** (N1/B3(i), N2/B-3 — rev1 keyed the drop on four codes and missed the open-time aggregates rows 9/10/11 (`app.rs:890-941`) and typed shared-code panel notes (§5 table; a `chat_ui.rs:1559` branch error persisted Open forever)). `IncidentObservation` gains `transient: bool` (default false), set at note time by **every §7 drain** (the eight `panel_observation` fns), **both recovery modals** (§7 rule 6), the **three open-time aggregates** (rows 9/10/11: LUT-store refusal, LUT-restore list, missing-media list — `app.rs:890-941`), and **all seven §5 codes** (N2/B-4 — every §5 note constructor sets it). The record builder drops **open** entries whose observation was transient and counts them in `WriteReport.dropped_transient_open`; **resolved** transient entries persist normally — they are history, not state. `observe` copies the bit onto the `Incident` as a `#[serde(skip)]` field (no wire change); `records()` drops open entries with the bit set. The record carries no provenance field, so every restored entry is non-transient — transient opens never reach a record, and resolved entries need no provenance after restore. The open pass re-observes whatever still stands (panels) or re-aggregates (unknown codes); persisting transient opens would pin yesterday's worker strings and yesterday's aggregates against today's. Enforcement is at write, not at restore: restore is faithful to the records it is given (§3 rule 10), and a hand-written sidecar carrying a transient-code Open loads it.
13. **`get_incidents` is unchanged**: no new argument, no pagination (`server.rs:1791-1817`; args at `:11803-11811`). The session log keeps today's unbounded behaviour within a run; the persisted cap bounds only the reload cost. Worst-case arithmetic from the probe's column (E-B10): 256 × 2 457 = **628 992 B (~629 kB)** measured-worst, 256 × 4 096 = ~1 MB ceiling — no pagination needed, and pagination stays IN3's (§15 item 1). Note `get_incidents` defaults to open-only (`server.rs:1800-1804`, critic S4): the persisted resolved backlog costs nothing until asked for.
14. **Privacy** (N1/S6, N2/S-5). The sidecar travels with the project file and shares its trust boundary — no new rule for proposal summaries/explanations, harness/model identity or spend, which persist verbatim. The one exception is `telemetry.resolver.stop`: harness and observer error text is arbitrary process output (paths, auth errors) and persists as its **category only**. Mechanism, in two halves: (a) the app prefixes payload stops at build — `resolver(&message)` becomes `"harness: {message}"` (`investigator.rs:1580`) and `resolver(&reason)` becomes `"observer: {reason}"` (`:1603`) (§0.4 d14; the live card gains the stop kind, which is the honest text); (b) core's record builder applies pure `persisted_stop(stop)` against **one `const STOPS: [&str; 17]`**: verbatim iff `stop` is in `STOPS` — `"completed"` (`:1520`, `:1536`), `"budget: turns"`, `"budget: wall time"`, `"budget: tokens"` (`:1542-1544`), `"the session asked for a confirmation"` (`:1560`), `"the agent event stream disconnected"` (`:1570`), `"the investigator was switched off"` (`OFF_SWITCH_STOP`, `:1092`, used at `:1615` and `:1665`), `"the investigator session ended unexpectedly"` (`:1640`), `"the investigator session could not start"` (`:1321`), `"re-investigated"` (`:2179`, `:2183`), `"interrupted: Kinewright closed"` (§3 rule 4), `"the project was closed"` (`app.rs:994` via `stop_threads` → `shutdown_for_close`), `"Kinewright is closing"` (`app.rs:1031` likewise), `"the incident was resolved elsewhere"` (`:1678`), `"the proposal conflicted twice against the live timeline"` (`investigator.rs:2044`), `"the live timeline refused the proposal"` (`:2052`), `"the proposal carried no operations"` (`:2064`) — else `"harness"` for the `harness: ` prefix, `"observer"` for the `observer: ` prefix, else the defensive `"session"` (reachable: `return_proposal_open_with_stale(.., &error.to_string())` at `investigator.rs:2072` carries arbitrary error text and persists as `"session"` — item 9 asserts it with a fixed example). **Record-size estimate.** The worked envelope below measures **~530 B** with one record (rev1's 488 B + the `previous_digest` line, N2/S-1); BP7's 3-incident file measured 2 370 B (~790 B/record with two evidence-heavy entries). The bound holds with 3–4× headroom where it matters (real logs) and exactly where it must (adversarial logs).

Shapes the example pins (all from the existing derives, verified): `subject` externally tagged snake_case (`incident.rs:909-911`; `{"asset":3}`, and unit subjects are bare strings — `"project"`, `"export_job"`, `"agent"` per the `:907-908` doc); `evidence` snake_case (`:965`); `state` flattened adjacently tagged (`:1095`, `:1359-1360` — `"state":"open"`, `"state":"resolved"` with `"outcome"`); `revision` transparent (`actor.rs:29-30`); absent `Option`s omitted (rule 3).

`WriteReport` is the write side's contract with the gate (§12 clause 2): `written_open` (records emitted for open entries), `written_resolved` (records emitted for resolved entries, ≤ 256, by `IncidentId`), `dropped_transient_open` (rule 12's transient opens), `pruned_resolved` (oldest-first overflow). The four sum to the log size minus nothing: `written_open + written_resolved + dropped_transient_open + pruned_resolved == log.len()` — item 7 asserts the identity, so a miscount fails loudly instead of silently dropping history. Carried opaque values (rule 8b) are re-emitted alongside but counted nowhere — they are not log entries.

**Why the digest is over bytes, not over the parsed document.** Re-serialising the document and hashing that would couple the pairing to serde's formatting (pretty vs compact, key order, float rendering). Hashing the exact bytes the save wrote couples it to nothing: the load recomputes over the exact bytes it read. A file copied, renamed or round-tripped through another tool keeps its bytes and its pairing; a file with one byte changed does not. FNV-1a 64 is 16 hex chars, dependency-free, and fast enough to run on every save and every load without a thought (the project file is kilobytes).

**The unsaved → saved transition.** A new project accumulates incidents in memory with no sidecar (rule 10). On first save: the save path serialises the document, computes the new digest, writes the full live log first (carrying `{new_digest, ""}` — there is no previous save), then the project bytes land and `saved_digest` updates (rule 9's sidecar-before-project order; pruning applies on every write — a first save with fewer than 256 resolved simply prunes nothing). The transition is one-directional within a session: after the first save the project has a path and every rule applies. Multi-project sessions flush per project (one sidecar per path); the flusher iterates open projects, and a failure on one project's sidecar notes into that project's log only.

**Flush scheduling.** The debounced background flusher is a single timer, not a thread per project: it wakes at most 2 s after the last log mutation on any open project — where "mutation" is `generation()` moving (rule 4), not a scan of entries — builds records on the frame thread under a read lock, and hands the bytes to the ONE writer thread (rule 5). Close/exit/save send their jobs and *join* the writer thread — returning before the bytes land would reintroduce B1's exact bug. A flush that finds `generation() == last_written_gen` skips the IO entirely (the digest pair would be identical anyway — no torn-write window is opened for nothing). Sequencing is by (path, seq): a save's job for a path always carries a higher sequence than any in-flight background job for that path, so the background bytes can never land after the save's (the clause-1 gate box asserts exactly this). Crash-consistency is §13 limit 7: the sidecar is history, and history lags reality by at most one debounce window.

**The rejected alternatives, in full.** A `Document` field was the brief's first rejection and N1's silence keeps it rejected: beyond undo/branches and the 52-site toll, it would put the log inside `validate()` (`model.rs:1303`), inside every branch's snapshot, inside the 1 215 B fixture pin, and inside the agent branch protocol (a branch core would need the log or explicitly not need it — a design question with no good answer). A per-user store was the brief's second rejection, reworded per N1/S5: its defects are (1) identity — incidents name asset ids and revisions that exist only in this project, so the store needs a project key that is the path by another name; (2) travel — "open the project on another machine", Q0's own case, silently drops the history; (3) ownership — two checkouts of one project fork the history with no merge rule. The sidecar has none of the three: the path IS the key, the file travels beside the project, and last-writer-wins (§2 rule 10) is at least explicit.

## §3 Restore

1. **Core gains `IncidentLog::restore(&mut self, records: Vec<IncidentRecord>, carried: Vec<String>, opening: TimelineRevision) -> RestoreReport`** (N1/S2, N2/B-6), writing INTO the shared `IncidentLogHandle` (`project.rs:246-250`, `:292`), never swapping it — every MCP server holding the handle sees the restored log with no re-subscription. `next_id` resumes above the loaded maximum. The report is §0.4 d6: `restored_open`, `restored_resolved`, `unknown_codes: Vec<(String, usize)>` (one entry per distinct unknown string, in first-seen order), `rebased` (records whose stored revision differed from `opening`), `carried` (the passed-through raw texts, untouched), `refused: BTreeMap<IncidentId, Operation>` (every record's `refused_op`, keyed by the record's `id` — rule 13). **Restore requires an empty log** (N-3): `debug_assert!(self.entries.is_empty())`, and the app calls it once per session creation, inside `ProjectSession::create` (rule 5's `SidecarMode::Load`), **before any note** — no observation is queued before restore runs, so no id can collide and no dedup can pre-empt a restored entry.
2. **Restore recomputes everything derived and trusts nothing derived** (brief §4, carried). For each record with a known code, restore resolves `class` via `policy_class`, `severity` via `policy_severity`, `field` via `code.field()`, and `recoveries` via `policy_recovery` — the single producer IN1 §9 clause 6 pins — exactly as `observe` does (`incident.rs:2923-2925`). A loaded incident therefore always agrees with the *current* policy table, including rows Part B's own seams newly reach. `evidence` (d13: fully owned) and `message` strings are taken verbatim; `count`, `allowed`, `subject_name` and `refused_op` are taken verbatim; `telemetry.resolved_after` restores as `None` (N-9 — the record never carries it, §2 rule 3); `proposal` is taken with `operations == []` and `stale` forced `true` (rule 7); `revision`/`base_revision` are rebased (rule 9); `opened_at` is set to `Duration::from_nanos(opened_offset_nanos)` — the loaded incident keeps its session order as an offset from the new origin.
3. **`from_code(&str) -> Option<IncidentCode>` scans `POLICY`** (N1/S2, E-B8): `POLICY.iter().find(|e| e.code.code() == code).map(|e| e.code)`. Total over all 74 codes (§5, E-B9); unknown (including `""` and wrong-case) → `None`. Probe BP6's 67-arm generated match (74 lines, verified round-tripping) is **not** used: a scan cannot disagree with the table it scans, and at ≤ ~300 records per load the linear scan is unmeasurable. §12 asserts the round trip over all 74 plus 3 unknowns (BP6's shape).
4. **`Investigating` is written as `Open`** (N1/S3, critic S3) — at write, never at load. The record builder takes an optional core struct `RunningInvestigation { id: IncidentId, harness: String, model: Option<String>, turns: u32, input_tokens: Option<u64>, cached_input_tokens: Option<u64>, cache_creation_input_tokens: Option<u64>, output_tokens: Option<u64>, reasoning_output_tokens: Option<u64>, cost_usd_millionths: Option<i64> }` — plain data only, no agent types in core — that the app fills from the running session's config, counters and last cost event (the resolver is `None` while running, `incident.rs:3101-3113`, and `SharedCounters` is never written to the log — the critic's two traps; the app maps its `SessionCost`/cost event onto the seven plain fields). The written record reads `Open` with `telemetry.resolver = Session { harness, model, stop: "interrupted: Kinewright closed" }` (exact string), `turns` and the six mirrors flushed exactly as a live end writes them. No suppression is written (IN2 §3.7 rule 38: only a person's decision resolves). Defensive arm: an `Investigating` entry with no running session behind it (unreachable through Part A — E-C2 never leaves one — but reachable through a hand-built log) is written with `harness: ""`, `model: None`, the `investigator.rs:2101` `session_resolver("", None, stop)` precedent.
5. **An `Investigating` in a record at load becomes `Open`** with the rule-4 stop. The writer never emits it (rule 4); only a hand-written sidecar carries it. The loader maps it rather than refusing the file: one bad row must not destroy the person's todo list (§2 rule 8's philosophy).
6. **Unknown codes are skipped, counted, and reported once** (brief §4, N1/S13·N10, N2/N-6). Restore is a pure function from (records, opening) to (log entries, report); everything agentic happens after, through the same paths live incidents take.

**The restore algorithm, in order.** The loader splits the envelope's `records` array per element (`RawValue`, §2 rule 8b): unparseable elements pass into `RestoreReport.carried` untouched. For each parsed record: (1) `from_code` the string — `None` feeds the rule-6 aggregate (skipped, counted); (2) recompute `class`/`severity`/`field`/`recoveries` (rule 2); (3) map record `Investigating` to `Open` with the rule-4 stop (rule 5); (4) force proposals `stale` with `operations == []` (rule 7); (5) rebase `revision`/`base_revision` to `opening` (rule 9); (6) set `opened_at` from `opened_offset_nanos` and file `opened_wall_millis` in `loaded_wall` (rule 14); (7) assign the record's `id`, resuming `next_id` above the max; (8) key `refused_op` into `report.refused` by `id` when present (rule 13). Then the app inserts every restored open id into `loaded_ids` and `loaded_open_ids`, resolves every subject against the loaded document (rule 17), merges `report.refused` into `refused_by_id`, and enqueues **nothing**. The whole algorithm is deterministic over (records, opening): the same sidecar restores the same log, which is what makes items 2–6 stable tests rather than golden files.

**Recompute vs persist, the complete table.** Persisted verbatim: `id`, `code`, `subject`, `observed`, `allowed`, `evidence`, `count`, `state` (modulo rule 5), `telemetry` (modulo rule 14's stop and N-9's skipped `resolved_after`), `proposal` minus operations (modulo rule 7), `subject_name`, `refused_op` (modulo d5), `revision` (modulo rule 9), wall + offset. ## §4 The version gate

1. **The version lives in an app-side file envelope over a core-owned constant** (N1/B5, N2/S-7, P1 — rev1 declared the const app-side, which strands `kinewright-eval`: the dependency edge runs app→agent (`crates/kinewright-app/Cargo.toml:15`), and `crates/kinewright-agent/Cargo.toml` names no `kinewright-app` — there is no reverse edge). Core gains `pub const PROJECT_FORMAT_VERSION: u32 = 1` plus pure `pub fn project_format_version(bytes: &[u8]) -> u32` (missing key → 1, present → its value; never fails — malformed bytes are the caller's `Corrupt`, not the reader's), both beside `Document` in `model.rs`. The app declares `ProjectFile { format_version: u32, #[serde(flatten)] document: Document }` in `project.rs` beside `write_project_document`, using core's const. `format_version` carries `#[serde(default = "v1", skip_serializing_if = "is_v1")]`: missing parses as 1 (every legacy file), and a v1 write is **byte-identical** to today — the 1 215 B `pre_m13_project.json` pin and the 52-edit precedent are untouched until the first real bump (P1 measured identical three ways: sparse 1 891 B, rich 1 970 B, empty 1 017 B; no flatten interaction — `model.rs:1098` carries no struct-level serde attribute, no `format_version` key exists in the `Document` subtree). **Save As from a newer-format session, walked through.** The person opens a v2 file in this v1 build (rule 4: opens, 1 incident, `session.format_version == 2`), presses Save As, picks a new path: the app writes current-version bytes (the v2-only fields are already gone from memory — dropped at parse) with `format_version` skipped (v1-identical, rule 1), drops the open `project_newer_format` incident from the live log (N2/B-4, §2 rule 7 — the note was about the old path), writes a fresh sidecar carrying the live log (rule 5's sibling §2 rule 7), and sets `session.format_version = 1` for the new path. Overwrite-save re-enables — for the new path only.

**Why overwrite-save is disabled but Save As is allowed.** The in-memory document has already lost the newer writer's fields (dropped at parse — serde gives no other option without `deny_unknown_fields`, which would refuse the open instead). Overwriting would launder that loss into the original file with no recovery. Save As writes the loss into a *new* file the person chose, with the card explaining — the same shape as "export to an older format" everywhere else. The original file is never modified by a build that cannot fully read it: that sentence is the whole of D1's fact 2, and item 18 asserts its UX.

**Why seven codes, not fewer.** The four sidecar/project codes could merge into one `persistence_issue` — but their severities, bodies and remedies differ (Save As vs reopen-newer vs next-trigger-retry), and merging them would put four distinct person-actions behind one card. Seven is the count at which every code has one remedy: the IN1 §2.2 rule 5 discipline (codes are (subject, failure) pairs with distinct recoveries) applied to untyped notes.

**Why these four field values.** `field` is "the stable field the failure is about" (`incident.rs:618-637`): panel notes are about the `panel` (the computation surface, not the underlying domain — the domain is gone with the flattening); recovery notes are about `recovery` (the subsystem); the newer-format note is about the `project` (the file); sidecar notes are about the `sidecar` (the history file). No new field joins the existing vocabulary except where none fits — `panel`, `recovery` and `sidecar` are new values, `project` is reused — and the card renders them as-is (lowercase, stable).

**Why `Always`, not a new predicate.** `PolicyPredicate` governs the *class* ("the condition under which the declared class survives", `incident.rs:1832`), not sessions — sessions are governed by the allowlist const. A `Never` predicate would be a session concept smuggled into a class column. The seven are `Explain` unconditionally (no probe can change that — their evidence is `Plain`), so `Always` is the honest value, and IN2 §3.1 reason (2) is the honest reason they are off the list.

**The allowlist test passes unmodified — and why that is load-bearing.** `in2_the_allowlist_is_fifty_four_…` asserts the const equals `POLICY[13..67]` in order. The seven rows land at indices 67–74, outside the slice, so the assertion holds byte-for-byte. If a future editor appends an eighth row *inside* the range (reordering variants), the test fails — contiguity is the tripwire IN2 §3.1 rule 3 installed, and this contract does not move it.

**Session economics, per code.** Why each of the seven earns reason (2) — what a session would do with the note, and why that is restating:

1. `panel_worker_error` — the session's whole input is the worker's string (already on the card) plus a `Plain` tag. No tool re-requests a proof/mask/transcription from a string; the panel retries on its own. Restating, plus a model call.
2. `recovery_damage` — the session cannot answer the dialog (a person's decision about their unsaved work). It would summarise the damage labels the dialog already shows. Restating, plus a blocked decision.
3. `recovery_unavailable` — the only remedy is save-and-restart (a person's file decision), and the recorder's error string is already on the card. A session cannot repair the recorder from inside the process. Restating, with tools that cannot help.
4. `project_newer_format` — the only actions are Save As (a person's file decision) and "open in the newer Kinewright" (outside this process). A session can do neither. Restating, with tools that cannot help.
5. `sidecar_unknown_codes` — the records are skipped by design; the session cannot read what this build cannot parse. It would count the report the card already summarises. Restating.
6. `sidecar_refused` — the file is kept for a newer build; the session cannot repair JSON it cannot parse (and must not delete it). Restating, with a destructive temptation nearby (reason to keep it off the list twice over).
7. `sidecar_write_failed` — an IO failure the next trigger retries. A session cannot fix disk permissions or a full disk from inside the process usefully — and the card already says the history is live. Restating.

The converse discipline: any future note whose session *could* act (re-request, re-measure, re-plan) takes a typed, allowlisted code instead — the §7 table's typed rows are the pattern, not the seven.

| --- | --- | --- |

## §13 Measurement limits, and what the implementer still measures

**Limits Part B records rather than papers over.**

1. No field Part B adds can warn an already-shipped older build (E-B7 fact 1). The installed base downgrades silently; the gate binds future pairs only.
2. Two processes on one project are last-writer-wins (§2 rule 10). One writer's tail can be lost; temp+rename removes only the torn reads.
3. The digest catches file mix-ups, not adversaries (FNV-1a 64, §0.4 d2). A malicious sidecar is parsed as data — `from_code` rejects unknown codes, serde rejects malformed JSON — but the pairing is not a security boundary.
4. The live log is unbounded within a run; only the persisted log is capped (§2 rule 13). A multi-thousand-incident session paginates nothing — IN3's if production logs show the need (§15 item 1).
5. Cross-run `observed` duplicates for non-panel codes are accepted (d12): a temp path that changes between runs opens a second incident. Deduplication is per-run by key, not semantic across runs.
6. Wall recency is best-effort wall order: clock skew across machines can misorder two incidents' millis, and `None` stamps show no recency rather than a lie (§3 rule 14).
7. The 2 s debounce is a bound, not crash-proofing (§0.4 d4): a crash loses log changes since the last flush (≤ 2 s of background writes, plus anything on a close path that never ran). The sidecar is history, not a journal — the recovery journal stays the crash story.
8. The ceiling worst is over the loop's shapes, not over all possible incidents (IN2's limit carried): a model-written proposal string at the 240 B cap and a 64 B name are the loop's extremities; the `assert` in production is the backstop, not the loop.

**What this draft deliberately does not pin.** Sidecar byte sizes per incident (records vary with evidence — only the 629 kB worst case is bounded); flush timings (the 2 s bound is a ceiling, not a measurement); the loop's post-Part-B shape count (unasserted per IN2's rule); session token/turn counts for panel notes (harness-dependent — clause 6 asserts ends, not cost); `.bak` retention (forever — disk is cheap, history is not). Anything else a reader wants pinned is either in §12 or a draft defect.

**Sidecar vs journal, the division of labour.** The recovery journal answers "what was the document when we crashed" (ops + initial document, strict version gate, ephemeral — deleted on clean close). The sidecar answers "what did the log hold when we last flushed" (incidents, lenient arms, durable — lives beside the project). They overlap only at recovery restore (§4 rule 5: the journal's document pairs with the sidecar's log, digest-less by necessity). Neither replaces the other: the journal cannot hold incidents (it replays document ops), and the sidecar cannot hold unsaved document edits (it flushes the log, never the timeline).

**What to watch after ship.** Three production signals tell whether Part B's bounds hold: (1) sidecar file sizes in the wild — consistently near the 629 kB worst case means the 256 cap wants revisiting (IN3's call, §15 item 1); (2) `.bak` accumulation — a growing pile of `.bak` files beside projects means digest mismatches are common, i.e. people routinely move project files without sidecars (a UX problem, not a bug — the arm is doing its job); (3) prune rates — `pruned_resolved` consistently near 44 per write means the log churns faster than the cap assumes (same IN3 call). None is instrumented in Part B (no telemetry framework exists for it); the signals are file sizes and incident counts Riel can read off disk.

## §14 Hand-run checklist

For Riel, against a real harness and a real display — the behaviours no `cargo test` reaches (all gate-adjacent behaviour is in §12; this list is the person-visible remainder). Prerequisites: a debug build (`source ./scripts/setup-ffmpeg.sh && cargo run -p kinewright-app`), a configured harness (item 1's proposal needs a real model — scripted drivers do not write real proposals), a display (`DISPLAY` set), and two scratch projects (A and B for item 5) plus one scratch copy for item 4's JSON edit. Budget each item at five minutes except item 1 (one real session, whatever it costs) and item 6 (one kill plus one restart).

1. **Reopen with open incidents.** Open a project, provoke ≥ 2 incidents (recipes below), run one to a proposal with a real harness, close **without** saving, reopen: the badge reads the loaded open count; every card renders with evidence, observed name and recency ("opened N minutes ago", not "just now"); the proposal renders stale with **Re-investigate** and no **Approve**; nothing re-ran (§§2–3, clause 1's visible half).

**Provocation recipes** (all manual, all at 04651e1): a relink refusal — rename a source media file on disk, then trigger the relink prompt; a LUT refusal — import a malformed `.cube` file (truncated ASCII); a panel note — break the transcription (point the model path at an empty dir, if the build exposes it) or fail an export verification (corrupt one frame of an export's source after the encode starts); a newer-format incident — item 4's JSON edit. Any two distinct incidents serve item 1; the proposal needs a real harness (Investigate → wait for the proposal → close without saving).
2. **The Investigate button.** On the reopened project, a loaded allowlisted row shows **Investigate**; press it: a session starts for that incident (turn/token/time counters tick); the button is gone after the press; a loaded `panel_worker_error` row shows no Investigate (§3 rule 12, §5 rule 4).
3. **No session on load.** Reopen the project from item 1 with no press and wait 60 s: no session starts, no budget is spent, the harness stays idle (check the harness's own usage, not just the UI) — §3 rule 12's whole point.
4. **Newer-file open.** Copy a project file, insert `"format_version": 999` after the opening brace, open it: the project opens; exactly one `project_newer_format` card explains; File → Save is disabled (and Ctrl+S re-surfaces the card instead of saving); File → Save As writes a working copy that reopens with no incident (§4 rules 3–4).
5. **Mismatched sidecar.** Open project A (writes A's sidecar), then copy B's `.kinewright` file over A's path keeping A's sidecar (or vice versa): open → exactly one `sidecar_refused` card, empty history, and a `.bak` beside the project with the refused bytes (first-free — a second refusal lands `.bak.1`); the project itself is untouched (§2 rules 8–9).
6. **Recovery with history.** With unsaved edits and ≥ 1 open incident, kill the app (not via Close), restart, take the recovery dialog: the damage note (`recovery_damage`) is in the log beside row 28; the recovered document pairs with the last-saved sidecar (revisions rebased — no aliasing weirdness in the panel); the first save rewrites both files (§4 rule 5, §7 rule 6).
7. **The debounce bound (optional, destructive).** Provoke one incident, `kill -9` the app within a second, reopen: the incident may or may not be there (≤ 2 s of history is the crash window, §13 limit 7). Repeat with a 3 s wait before the kill: the incident is always there. This is the only item that asserts timing, which is why it is hand-run and optional.

**Expected outputs, so "looks right" is checkable.** Item 1: badge number equals the pre-close open count; each card's recency reads minutes/hours (never "just now" for a loaded incident, never a wall date — recency is relative); the stale proposal card shows its `operation_count` ("3 operations proposed") with Re-investigate. Item 2: Investigate renders beside the severity chip (same row as Re-investigate does on live rows); after the press the row shows the session's live counters. Item 4: the Save menu item is greyed with the tooltip naming the newer version (implementation's words, reviewed in the app pass); the card's body is §5 rule 1 #4 verbatim. Item 5: the `.bak` file's bytes equal the refused sidecar's (diff them); the card's body is §5 rule 1 #6 verbatim. Item 6: the recovered document keeps its pre-crash revision (recovery restores the document, it does not restart the counter); loaded incidents rebase to it (S1), so the panel shows no revision aliasing.
