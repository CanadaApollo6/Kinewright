# Codebase Audit — August 2026

Scope: SOLID, DRY, code-as-cost, and runtime efficiency, per the project's
standing bar: *ruthlessly efficient and optimized, with trust, security, and
correctness guarantees as non-negotiable invariants.* Conducted by the
orchestrator after M10; every efficiency claim below is measured, not guessed.

## Findings, ranked

### F1 — DRY: three parallel derived-data infrastructures *(highest value)*
`transcript.rs` (895 ln), `analysis.rs` (619 ln), `derived.rs` (1,266 ln) each
implement their own background worker, content-addressed cache directory
resolution, corrupt-entry recovery, and — the smoking gun — private copies of
`sha256_file` (×3, despite `sha256.rs` existing), `atomic_write` (×2), and
memoized `content_hash` (×2). The M10 brief said "cached exactly like
transcripts" and that is literally what happened: by copying.
**Remediation:** extract one generic derived-data framework (worker + cache +
hashing + atomic IO + status reporting), instantiate four times. Estimated
−600 to −900 lines, one place to fix cache bugs forever. Mechanical-adjacent;
Codex-suitable under a tight brief.

### F2 — ISP: `MediaEngine` is a 17-method fat interface *(architectural — needs Riel)*
Playback transport (7), probe, thumbnail, export, and three analysis families
(transcript/silence/scene × request/status) share one trait. Consumers depend
on everything: the MCP server mocks playback methods it never calls; tests stub
export to test probing.
**Remediation options:** (a) facet traits (`Playback`, `Analysis`, `Export`)
composed by the engine, consumers take only their facet; (b) keep the single
trait, accept the coupling as the cost of one injection point. (a) is cleaner,
touches every consumer once. Decision surfaced to Riel with F3.

### F3 — DIP: the app holds `Arc<FfmpegMediaEngine>` concretely *(tied to F2)*
Partially forced: `visual_asset_results()` (waveform/thumbnail channel) isn't
on the trait, so the app needs the concrete type. A composition root touching
concrete types is fine; a concrete *field* propagates the dependency.
**Remediation:** fold the visual-results channel into F2's `Analysis` facet;
the field becomes `Arc<dyn ...>`. Resolves with F2.

### F4 — OCP: effects are stringly-typed in two places
Effect names/parameters are validated by `match` arms in core and interpreted
again in the compositor. Adding an effect means editing both, and nothing
forces them to agree.
**Remediation:** one effect descriptor table in core (name, params, ranges,
neutral defaults) consumed by validation, the compositor uniform mapping, and
the agent tool docs. Moderate; Codex-suitable.

### F5 — Efficiency: O(clips) apply is MEASURED FINE — leave it alone
The clone+validate-everything apply (the price of atomic rejection) scales
linearly and costs 126 µs per op on a 1,000-clip project — ~8,000 ops/sec,
three orders of magnitude above any human or agent editing rate. DoBatch
amortizes it further. **Verdict: acquitted with numbers. Do not optimize.**
Guard: add a core-throughput case to the gated perf suite so regressions and
future scale changes are caught by measurement, not anecdote.

### F6 — Efficiency, minor: op-log clones and unbounded growth
`Query::OpLog` clones the entire log per query; the in-memory log grows
unboundedly across a session (disk journal already covers recovery).
**Verdict: low priority.** Cheap fix (Arc entries / rotation) if long-session
memory ever measures as a problem; not before.

### F7 — Code-as-cost: test-support duplication
E2E and matrix tests re-implement env setup, TTS synthesis, and media
generation helpers per file. **Remediation:** a shared test-support module;
fold into F1's milestone.

### F8 — Tooling: lints configured but never enforced
Workspace enables `clippy::pedantic = warn`, but CI runs neither clippy nor
fmt; rustfmt was broken locally for weeks (now fixed) and 2,677 lines drifted.
217 pedantic warnings accumulated — unenforced lints are worse than none
(noise that trains everyone to ignore the tool).
**Remediation:** one-time `cargo fmt` + clippy cleanup sweep, then CI enforces
`fmt --check` and `clippy -- -D warnings`. Mechanical; do first so later
remediations land against an enforced baseline.

### F9 — Dependencies and binary: acceptable, keep watching
268 crates, 130 s release build, 28 MB binary. The heavy hitters (eframe/wgpu,
ffmpeg-next, whisper-rs, rmcp/axum/tokio, image, rfd) each earn their place;
no removable heavyweight found. No action; re-measure each audit.

### F10 — SRP: mostly healthy post-M5c
`app.rs` at ~820 lines is acceptable as the composition root; `derived.rs` at
1,266 lines housing two detectors plus infrastructure dissolves naturally
under F1. `decode.rs` (754) and `engine.rs` (632) are cohesive. No action
beyond F1.

## Invariants confirmed intact
Zero unsafe. Agent sessions locked down; confirmation broker on every
destructive path including batch plans; SHA-pinned downloads; credentials
never touched; per-record journal fsync; one render path. Nothing in the
remediation plan may weaken these.

## Remediation plan
1. **R1 (now, mechanical):** fmt sweep + clippy cleanup + CI enforcement (F8).
2. **R2 (Codex milestone):** derived-data framework extraction + test-support
   consolidation (F1, F7); effect descriptor table (F4). Full suite + gated
   tiers must stay green; no behavior change.
3. **R3 (Riel decision):** MediaEngine facet split (F2, F3) — recommended
   option (a), executed as its own reviewed change if approved.
4. **Standing:** core-throughput perf case added to the gated suite (F5);
   re-run this audit's baseline table at the next audit and compare.
