## CI-only fixes

- The archive builder packs Cargo fingerprints and dependency libraries into a separate hash-verified artifact. Only the shard with the public-API compiler probe downloads it. Nextest already carries the native linked-library directories.
- Every shard recreates `target/tmp` before execution. No product or Rust test source changes.
- All 17 Linux fast `te14_fix1_` tests run as a preserved serial libtest batch on a dedicated runner. Internal test concurrency and the two-second assertion remain unchanged.
- The complete `display::tests::` family runs as a preserved serial batch on a dedicated runner. Each media process remains single threaded. Its bounded deadline is 30 minutes, with a 35-minute job limit. Other test processes retain the ten-minute deadline.
- `.cargo/ci-test.toml` sets media test compilation to optimization level 2. Debug assertions and overflow checks are explicitly enabled. The same config is used by archive creation, listing, and doctests. No test body, ignore, tier, fixture, workload size, assertion, or tolerance changes.
- Archive jobs save Rust caches even if a later archive check fails. Existing cache key prefixes and environment remain unchanged. Windows archive setup skips the local build-cache prune. Cargo HTML build timings are retained for the next run.
- Linux keeps 12 fast shards. Windows uses 8 fast shards instead of 12. Both slow tiers keep 8 shards. The measured Windows workload fits the smaller matrix; four fewer jobs reduce scheduling pressure.
