Sensitive control/compiler batches still get exclusive runners. This uses spare capacity after short display cases and reduces queue pressure.
- Reuse canonical display inputs through the existing ignored PF1 preparation helper and existing frozen-input reader. No extra Rust source changes. The preparation helper runs separately on cache misses and must report its one real pass. Its unchanged builder writes the document and media, round-trips them through the existing reader, and verifies equality before a cache-ready receipt is written. The normal tier still observes that helper as ignored. The display test still runs all ten frames and all assertions against the original document/media bytes. `PF1_ONLY` is confined to the preparation subprocess; the display test retains its six-workload completeness assertion.

Before using a hit, check the receipt, workload manifest and every document/media file SHA-256. The existing Rust reader independently verifies hashes, media completeness and asset paths. Corrupted, missing, substituted or incomplete inputs fail; no fallback hides them. Cache save requires successful canonical preparation and its final ready receipt.
