# CI fast round 4: measured green run 42720633168

[Run 42720633168](https://github.com/CanadaApollo6/Kinewright/actions/runs/42720633168) at dbadbaf2 passed in **25m15s**, down from the previous failed 25m48s. The original whole-workflow bound was about 64 minutes. The display batch was the critical path.

## Changes for the next run

- Split the display parity test into six tests, one for each original workload. Each builds only its original workload through the same canonical builder and pinned-input fallback. The exact ten-frame formula, both render calls, readback assertion, premultiply calculation, length and byte equality assertions are unchanged. Comparison count: **6 workloads x 10 frames = 60 before and 60 after**. The final zero-live-bytes assertion now runs once per workload. No slow or ignored manifest entry names the old test, so neither manifest changes.
- The only Rust files changed are `crates/kinewright-media/src/display_tests.rs` and its test-only support module `crates/kinewright-media/src/pf1_harness.rs`. No product code changes. The latter extracts the six builders so each split case avoids regenerating the other five workloads. Existing PF1 callers retain their workload order, filtering and builders.
- Six display cases get separate runners. Linux fast has 18 shards and Windows fast 14; both slow tiers retain eight. Long integration batches above 120 seconds get exclusive runners when slots permit. The Linux app still uses its original complete batch: 355.19 seconds of tests, 429 seconds whole job. It cannot be split under the current scope.
- Replace stale unoptimized timing hints with successful measurements from this green run. The 191.16-second storage and 177.73-second rescue-record integration binaries no longer share a runner with the parallel tail; the former Linux shard 9 had storage plus 50.72 seconds of MCP plus its parallel tail and took 534 seconds.
- Timing hints are optional. A new selftest adds an unseen `te1` test to a compiled inventory, verifies exactly one shard includes it with the fallback estimate, passes exact coverage with its result, and proves coverage fails if that result is removed. It repeats with empty hints, stale removed-test hints and a missing timing file. Hints cannot define membership.
- Before compilation, try a locked offline host-dependency fetch. Fetch online only when that preflight fails, then build/list/doctest with `--frozen`. This avoids the observed 25–31 seconds of index/startup time on a complete cache without retrying a failed compiler or test.
