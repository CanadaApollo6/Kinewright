# Kinewright Colour Workflow v6

Benchmark id `kinewright-color-workflow-v6`. Contract: [`docs/CC7-WORKFLOW-EVALUATION.md`](../../../docs/CC7-WORKFLOW-EVALUATION.md).
Scenario authority: `kinewright_core::cc7_scenarios`. Source generator: `kinewright_media::cc7_sources`.

**Status: pending real-harness run.** Nothing in this directory records a measured
model result yet. CI runs the suite's *unit* tests — construction, packaging, the
manifest/ground-truth binding — and never runs a model.

## What this suite proves

Six named colour workflows, one model turn each, over the CC0–CC6 surface:

| id | Scenario | What the model is asked to do |
| --- | --- | --- |
| `c1` | (a) mixed-camera interview | Match a second camera to an approved reference without touching the reference. |
| `c2` | (b) wrong white balance, underexposed | Recover as far as the primary controls allow, and say where the authority ran out. |
| `c3` | (c) log-like input | Import an inverse `.cube` from disk and bind it at the input stage. |
| `c4` | (d) product and skin | Isolate one product patch without moving anyone's skin. |
| `c5` | (e) creative look | Apply a built-in look, prove the bypass, and report the gamut excursion. |
| `c6` | (f) tracked secondary | Track a moving subject and stop at the occlusion rather than invent a position. |

Every prompt names the clips and the intended outcome and **never names a
parameter or a value**: the point of the suite is to find out whether the model
can choose them.

This suite is the *model* lane. The same six scenarios are discharged
objectively by ordinary `cargo test` fixtures (CC7 §4) in the default GPU lane
on both CI operating systems, with no model and no network, and by scripted MCP
end-to-end tests (CC7 §5). **The technical gates do not need this suite**, and a
failure here is a statement about a model, not about the colour engine.

## Fixtures

No fixture bytes are checked in. `manifest.json`, `ground-truth.json` and this
file are the only files in this directory.

Every raster is authored in Rust from `cc7_scenarios`' analytic values and muxed
at fixture time as FFV1 `-level 3 -g 1`, `yuv444p`, BT.709 limited, `.mkv`, by
`kinewright_media::cc7_sources` — the *same* generator the technical gates use,
so a raster cannot drift between the two claims made about it. `c3` additionally
saves its project into a temporary directory and writes
`log_like_inverse_cube(65)` beside it as `log-inverse.cube`; it is the only task
whose `PreparedFixture` carries a `project_path`, and without one
`import_lut_asset` refuses `project_not_saved` and the task is unsatisfiable.

`ground-truth.json` carries, per scenario, the **canonical document** —
`canonical_document`, the effects, parameters and keyframes that
`cc7_canonical_operations` leaves on each clip when it is applied to that
scenario's initial document — beside the batch itself and the expected
measurements. It is **generated**, never hand-edited: it is written by
`cc7_ground_truth_json` in `crates/kinewright-agent/src/bin/kinewright-eval.rs`
and `published_v6_manifest_tracks_the_color_workflow_suite` asserts the
checked-in bytes equal the generated bytes. There is deliberately no environment
knob to regenerate it — when the two diverge the test prints the generated bytes
and the implementer pastes them, so a ground-truth change is always a reviewed
edit.

## How to run it

```sh
source ./scripts/setup-ffmpeg.sh
KINEWRIGHT_EVAL=1 cargo run -p kinewright-agent --bin kinewright-eval -- \
  --suite color-workflow-v6 --harness claude-code --samples 3
```

`--only c3` runs one task. `--samples 3` is what the acceptance target below
asks for. The run writes `target/evals/<run-id>/` containing `results.jsonl`,
`machine-report.json`, `artifacts/`, `human-review.json`, `blind-key.json`, and
`blind/`.

The unit tests, which is all CI runs:

```sh
cargo test -p kinewright-agent --bin kinewright-eval
cargo test -p kinewright-agent --lib
```

## The blind review procedure

The reviewer is handed **`blind/` and nothing else**, and opens **only**
`blind/review-form.json` plus the `blind/<blind_id>.png` and
`blind/<blind_id>.mp4` artefacts beside it.

- **Do not open `machine-report.json`.** It carries every machine verdict.
- **Do not open `blind-key.json`.** It is written to the run root, deliberately
  outside `blind/`, and it is what maps a `blind_id` back to a task.
- **Do not open `results.jsonl`, `human-review.json`, or `artifacts/`.**

The form is keyed on `blind_id` alone — a 12-hex prefix of the artefact digest —
and carries no task id, run id, benchmark id, harness, model, machine verdict,
assertion name, parameter name or parameter value.
`cc7_the_blind_package_discloses_no_machine_provenance` scans both the `blind/`
listing and the form's bytes for all of those and is proved able to fail on
each.

For every entry, rate `visual_finish` and `delivery_readiness` on the 1..=5
scale in 0.5 increments, answer every question in `questions`, and set
`accepted`. `story`, `pacing`, `audio_finish` and `captions` are pre-marked not
applicable: the colour suite renders no dialogue, no music and no captions, and
rating them would be fabrication. Two byte-identical artefacts share one
`blind_id`, so one viewing scores both rows.

Score the filled-in form with:

```sh
cargo run -p kinewright-agent --bin kinewright-eval -- \
  --score-review target/evals/<run-id>/blind/review-form.json
```

`--score-review` resolves each `blind_id` through the sibling `blind-key.json`
**before** the artefact bindings are checked, writes the unblinded
`human-review.json` into the run root, and refuses a `blind_id` the key does not
carry with a typed error naming it. A form presented without its key is a typed
error naming the missing path, never a silent fallback.

**What is deliberately not blinded: the scenario identity.** It is inherent in
the question being asked — *"Does the match preserve natural and intentional
differences?"* *is* the mixed-camera scenario — and a chart raster is
recognisable anyway. CC7 blinds the machine provenance and says plainly what it
does not blind. A reviewer who opens `blind-key.json` is unblinded; that part is
procedure, not something a test can bound.

## The human gate (CC7 §8.6)

For **each** scenario in the package:

> each passes **3/3** model samples against its technical gates; at least **2 of
> 3** outputs are accepted by a person; **every question is answered**; and the
> mean human rating is at least **4.0/5** over the applicable dimensions, N/A
> dimensions excluded. **One success does not satisfy the slice.**

Scenario (c) contributes **no** question: the roadmap's colour evaluation matrix
has no row for log-like input, so `c3` is objective-only. Scenario (g), encoded
delivery, contributes a question **only** when the verification raises a
`Warning`-severity exception — an encode whose only exception is the allowed
Info `delivery_tag_not_representable` is not reviewed, because there is no
trade-off to judge.
